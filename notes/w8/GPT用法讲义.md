#  GPT 用法讲义：把 LLM 当作一组可配置的工作工具

前一份 GPT 讲义主要解释大型语言模型（Large Language Model, LLM）如何训练、如何生成、为什么会幻觉、为什么需要工具。本讲义把视角转到实践：打开 ChatGPT 这样的应用之后，面对文本框、模型选择器、搜索按钮、思考模式、文件上传、代码解释器、语音、图片、视频、记忆和自定义 GPT，我们到底应该怎样理解这些功能，又应该怎样把它们用到自己的学习和工作里。

核心观点是：不要把 ChatGPT 看成一个单一的“聊天机器人”。更好的理解方式是：它首先是一个会在上下文窗口（context window）里续写 token 的模型；然后，产品层把不同模型、工具、文件、搜索、代码解释器、多模态输入输出和记忆系统接到这个模型周围。你使用的不是一个功能，而是一套不断变化的 LLM 应用生态。

本页先建立整节课的地图：今天讨论的不是“LLM 为什么能说话”，而是“LLM 应用到底由哪些可用能力组成”。

- 最中间的能力仍然是模型本身：它接收 token 序列，预测下一个 token，再把 token 一个个生成出来。
- 模型外面包了一层应用界面：聊天气泡、模型选择器、新建对话、文件上传、搜索按钮、语音按钮、移动端摄像头等，都属于产品层。
- 再往外看，是不同提供商和不同产品：OpenAI 的 ChatGPT、Anthropic 的 Claude、Google 的 Gemini、Microsoft 的 Copilot、Meta 的聊天体验、xAI 的 Grok、DeepSeek、Mistral 的 Le Chat、Perplexity、NotebookLM、Cursor 等。
- 使用 LLM 的关键不是只问“哪个模型最强”，而是根据任务判断：需要普通回答、思考模型、搜索、深度研究、代码执行、文件阅读、图片理解、语音交互，还是编程环境里的代理。
- 本讲目标是把这些按钮和功能背后的共同机制讲清楚，使学习者以后看到新产品时能自己判断它适合什么任务。

## 1. 从 ChatGPT 文本框开始：生态已经不是单一产品

上一讲已经深入解释了 LLM 的底层训练方式，以及应该如何理解它们的“认知”或“心理”。本讲不再主要讲训练原理，而是转向更实际的应用：通过文本框、模型选择、工具调用、文件上传、多模态输入和个性化设置，理解这些工具在学习、生活和工作中的典型用法。

首先打开的是 `chatgpt.com`。ChatGPT 由 OpenAI 开发并在 2022 年部署。它的重要性在于，这是许多人第一次可以通过文本界面，像聊天一样和大型语言模型对话。这个体验迅速在互联网上传播，造成了非常大的影响。

但到 2025 年，生态已经丰富很多。ChatGPT 是最早的大众化产品之一，也是最流行、功能最丰富的“老牌在位者”，因此很适合作为主线例子。不过，现在有许多类似 ChatGPT 的应用，有些只是相近的克隆，有些则提供了 ChatGPT 没有的独特体验。

大公司都推出了类似体验，例如 Google 的 Gemini、Meta 的聊天产品、Microsoft 的 Copilot。创业公司也很多，例如 Anthropic 的 Claude、Elon Musk 的 xAI 推出的 Grok。DeepSeek 是中国公司，Mistral 的 Le Chat 是法国公司。这些模型和应用可以通过网络搜索找到，也可以通过排行榜跟踪。

一个常见排行榜是 Chatbot Arena, 现在常叫 LM Arena。它通过人类盲评比较模型回答，并给出类似 Elo 分数的排名。另一个例子是 Scale 的 SEAL Leaderboards，可以查看不同评测任务上模型的表现。排行榜可以帮助我们知道当前哪些模型在不同任务上表现较强，但排行榜不能替代自己的任务测试。

本讲义后面会以 OpenAI 的 ChatGPT 为主线，因为它功能最完整、最适合把产品能力串起来讲；同时也会穿插 Claude、Gemini、Grok、Perplexity、NotebookLM 和 Cursor，说明不同应用的优势和差异。

## 2. 文本框背后：我们和模型共同写一个 token 流

LLM 最基本的交互形式，是用户输入一段文本，模型返回一段文本。比如可以让模型写一首关于“作为一个大型语言模型是什么感觉”的俳句（haiku）。这类任务很适合语言模型，因为它们本来就很擅长写作，包括诗、求职信、简历、邮件回复等。

在界面上，我们看到的是像朋友聊天一样的气泡：用户发一句，模型回一句。例如模型可能写出“文字像溪流一样流动、无尽回声、思想幽灵不可见”这类戏剧化的短诗。可是底层并不是两个“气泡对象”在对话，而是文本被切成小片段，也就是 token。用户查询（user query）和模型回复都会被变成一维 token 序列。

可以用 Tiktokenizer 之类的工具观察 tokenization。选择 GPT-4o 对应的分词器，把用户输入粘进去，就能看到模型真正看到的 token。在一个简单例子里，用户问题正好是 15 个 token；词表大约有 20 万个可能 token，每个小文本片段都有自己的 token ID。大小写、空格、拼写变化都会改变 token 序列。模型回复的俳句对应 19 个 token。因此，从数量上看，是用户写入 15 个 token，模型接着写回 19 个 token。

真实聊天还要保留角色和消息边界，所以底层会有对话格式（chat format）。应用会在 token 流中加入特殊 token，例如“用户消息开始”“用户消息结束”“助手消息开始”等。具体格式不重要，重要的是：我们看到的是来回气泡，底层却是用户和模型轮流往同一个一维 token 流里写内容。两轮简单气泡合起来，在对话协议里可能约是 42 个 token。

点击 New Chat 的意义，就是把这条 token 流清空，从零开始新的上下文窗口。用户写 token，按下回车后控制权交给模型；模型继续生成 token，直到生成某个表示“我说完了”的特殊 token，应用再把控制权交回用户。这样一来，用户和模型轮流扩展同一条 token 序列。

上下文窗口可以理解为本次对话的工作记忆（working memory）。窗口里面的内容对模型是直接可访问的；窗口外的内容就不在这次对话的直接记忆中。这个概念后面会反复出现：搜索、文件上传、深度研究、OCR、视频帧、记忆功能，本质上都是在想办法把有用信息放进模型能读到的上下文里。

### slide 2

本页把聊天界面翻译成底层机制。看到 ChatGPT 气泡时，很容易误以为系统内部也保存着“用户说了什么”“助手说了什么”两个自然语言对象；实际上，模型真正处理的是一条带角色标记的 token 序列。

- “New Chat”不是一个普通按钮，它等价于清空当前上下文窗口，让后续对话不再继承前面的 token。
- 用户输入并不是直接进入一个“理解模块”，而是先被切成 token，再连同 user/assistant 等角色标记一起放入序列。
- 模型回答也不是一次性写完整段，而是持续预测下一个 token，直到生成停止标记。
- 上下文窗口是工作记忆：只要信息在窗口里，模型就可以直接参考；如果信息不在窗口里，模型只能依赖参数中模糊压缩的知识。
- 后面所有工具都可以从这里理解：搜索是在往窗口里放网页，文件上传是在往窗口里放文档，OCR 是把图片里的文字放进窗口，记忆功能是把一些关于用户的摘要预先放进窗口。

要把握的动作感是：和模型对话不是把问题扔给一个黑箱，而是和模型一起写一条越来越长的 token 流。这个窗口越相关，回答越容易好；窗口越脏、越长、越跑题，模型越容易分心。

## 3. 模型本体：一个有损的互联网压缩包

前一讲把模型训练分成两个主要阶段：预训练（pre-training）和后训练（post-training）。预训练可以想象成把整个互联网切成 token，再压缩进一个“压缩包”。这个压缩包不是精确无损的，而是有损的、概率性的，因为不可能把整个互联网精确塞进一个一 TB 左右的文件。

压缩包里真正保存的是神经网络参数（parameters）。如果把一个大模型粗略想象成一 TB 文件，它可能对应约一万亿个参数。这个神经网络训练时做的事情，是在互联网文档上预测下一个 token。也就是说，预训练后的基础模型很像一个互联网文档生成器。为了预测下一个 token，它被迫学习世界知识、语言规律、写作风格和大量常见模式。这些知识都压缩在参数里。

预训练非常昂贵，可能要花数千万美元、训练数月。因此它不会频繁发生。以 GPT-4o 这类大模型为例，它的预训练往往在公开使用之前许多个月就已经完成。这解释了知识截止日期（knowledge cutoff）：模型参数中的知识只能到预训练时为止。后训练也可能带入一些新知识，但大体上，模型本身应该被看作有点过时。对于上周发生的事情、最近发布的产品、刚决定的电视播出时间，模型参数里通常不会有可靠记忆，需要通过工具把新信息提供给模型。

后训练像是在这个压缩包外面贴上一个“笑脸”。我们不希望模型只继续生成互联网文档，而希望它扮演一个能回答用户问题的助手人格。后训练把数据集换成由人类构建的对话数据，让模型学会用户提问、助手回答的风格。预训练提供知识，后训练提供助手形式和语气，两者合在一起，才形成我们在 ChatGPT 里体验到的对象。

但默认情况下，这个对象是自包含的。可以把语言模型想成磁盘上的一个一 TB 文件，里面有一万亿个参数，任务是根据输入 token 预测下一个 token。它本身没有计算器、没有 Python 解释器、没有联网浏览器、没有世界实时访问能力，也没有工具。你向这个“压缩包”流入 token，它向你流出 token。工具使用是后面额外接上的能力。

可以把模型拟人化地想象成这样一段自我介绍：你好，我是 ChatGPT，我是一个一 TB 的互联网有损压缩包；我的知识来自大约六个月前读完整个互联网，但我只记得模糊轮廓；我讨人喜欢的性格，是 OpenAI 的人类标注员通过示例“编程”出来的。频繁出现在互联网上的知识，我记得更好；罕见知识，我记得更差。这和人类记忆有一点相似。

### slide 3

本页给出本讲最重要的心理模型之一：默认情况下，你不是在和“联网智能体”说话，而是在和一个有损压缩包说话。

- 预训练把互联网文本压进参数，所以模型有大量世界知识，但这些知识是模糊、概率性、可能过时的。
- 后训练让这个压缩包呈现出助手人格，所以它会回答问题、解释概念、道歉、拒绝某些请求，而不是单纯续写网页。
- 知识截止日期来自预训练时间。近期新闻、最新价格、刚发布的产品功能、刚更新的 API，通常不应只靠参数记忆。
- 默认模型没有工具。没有搜索、没有计算器、没有 Python、没有文件系统、没有实时网页，除非应用额外接入这些能力。
- 因此，使用 LLM 的第一步是判断：这个问题能靠压缩包里的模糊常识回答，还是必须把新材料或工具接进来。

“zip file”不是贬义，而是使用指南。压缩包很有用，但它不是数据库，也不是浏览器，更不是医生、律师或财务顾问。正确使用它，要知道什么时候可以让它凭常识回答，什么时候必须查证。

## 4. 哪些问题可以直接问：常见、非近期、低风险

可以用两个生活例子说明什么时候可以直接问模型。

第一个例子是咖啡因。可以直接问 ChatGPT：一份美式咖啡（Americano）的一份 espresso shot 里大约有多少咖啡因？如果要把它和抹茶（matcha）比较，模型可能回答大约 63 毫克。这个问题适合直接问，是因为它不是近期知识，咖啡因含量没有最近突然改变；同时，它在互联网上非常常见，相关信息出现次数很多，模型应该有较好记忆。不过，这并不保证正确；它只是模型对互联网的模糊回忆。可以去查主要来源或其他资料验证，而结果看起来大约正确。

第二个例子是感冒流鼻涕。用户可以告诉 ChatGPT 自己有点病、流鼻涕，想找能帮助缓解症状的药。模型可能给出一些建议；如果进一步澄清主要希望鼻子不流，并询问 DayQuil 和 NyQuil 是否有用，模型会分析 DayQuil 和 NyQuil 的成分以及它们是否缓解流鼻涕。这里不能完全相信模型，而应拿出药盒核对成分，确认 NyQuil 的成分是否确实和模型说的一样。这个用法可以接受的前提是：DayQuil/NyQuil 是常见药，网上资料很多；这不是高风险情境；用户还做了核查。之后继续询问 NyQuil 大约多久起效，也属于常见、低风险、可核查的信息咨询。

这个例子同时给出边界：模型可以做知识型咨询的初稿，尤其是常见、非近期、低风险的问题；但如果涉及医疗信息，仍然要核对来源，必要时问医生。模型的回答是概率统计回忆，不是权威处方。

## 5. 管理上下文：切换主题就开新对话

第一个操作建议是：只要切换主题，就尽量新建对话。原因是上下文窗口里的 token 很宝贵。

第一，过长的上下文会分散模型注意力。上下文窗口是工作记忆，里面如果塞满了上一件事的无关 token，模型在后面生成回答时可能被这些信息干扰，准确性和表现都会下降。

第二，窗口越长，生成下一个 token 的计算成本越高。这个成本增加不一定很大，但确实会让模型略慢、略贵。因此，应该把上下文窗口看作珍贵资源。与当前任务相关的信息应该保留；不相关的信息应尽量清掉。最简单的实践就是：换话题，点 New Chat。

### slide 4

本页给出一个很实用的判断框架：什么时候可以直接问，什么时候不要直接问。在数学学院大三阶段，例子可以落在课程学习、作业、竞赛和日常校园事务上。

- 可以直接问的典型问题：常见数学定义回顾、LaTeX 表格或公式写法、英文邮件初稿、低风险学习建议、课程项目头脑风暴。
- 直接问时仍然要记住：模型是有损回忆，不是引用数据库。比如“什么是 Cauchy 列”“怎么写一个 `align` 环境”这类问题适合直接问，但仍要用教材或编译结果核对。
- 需要问后核查的典型问题：课程安排、奖学金政策、数学建模竞赛通知、图书馆开放时间、学院讲座时间。这些信息可能变化，应查官网或通知来源。
- 不适合只靠直接问的典型问题：近期通知、高风险医疗金融法律建议、课程政策细则、精确计算、严格证明、数值实验结论。
- 上下文管理也属于“怎么问”的一部分。无关历史越多，模型越容易被干扰；新话题最好新建对话。
- 如果相关材料很长，应该主动整理或上传，而不是指望模型从过去很多轮闲聊中自己找出重点。

“直接问”不应只是默认行为，而应是一种经过判断的选择。直接问不是不可以，而是要满足常见、稳定、低风险、可核查这几个条件。

## 6. 模型选择和价格层级：你实际在和哪个模型说话

第二个操作建议是：始终知道自己正在使用哪个模型。ChatGPT 左上角通常有模型选择器。不同模型有不同大小、能力、速度、价格和工具接入情况。

如果不登录，或者使用免费层，可能不是在用 GPT-4o，而是在用更小的 GPT-4o mini。免费层可能能有限访问 GPT-4o 和 o3-mini，但界面有时不清楚显示当前模型。更小模型通常参数更少，写作不如大模型好，知识没那么强，也更容易幻觉。

ChatGPT 对个人用户有 Free、Plus、Pro 等不同层级。Plus 曾经约每月 20 美元，并可能有 GPT-4o 每三小时 80 条等限制；Pro 曾经约每月 200 美元，提供更多功能和更高限额，包括无限 GPT-4o 和一些高级能力。具体价格和限制会变化，使用时应该看当前界面和官方说明。

其他 LLM 提供商也类似。Claude 有自己的付费计划，付费后能访问 Claude 3.5 Sonnet 等更强模型；不付费可能只用到较弱模型。Gemini 和 Grok 也有模型选择器和高级层级。选择模型时，应根据自己的任务和预算选择足够强的模型。如果是职业工作，例如大量编程，付费使用顶级模型可能非常划算；如果任务简单，便宜层级可能够用。

还可以把多个模型当作“LLM 委员会”（LLM Council）。比如旅行建议，可以分别问 Claude、Gemini、Grok 等不同模型，比较它们的想法。一个典型例子是询问 Claude 推荐一个很酷的城市，Claude 推荐瑞士 Zermatt；Gemini 对类似问题也可能推荐 Zermatt。这类旅行建议和灵感发散，适合多模型交叉询问，然后自己进一步研究。

本页强调：同一个产品界面里，背后可能有完全不同的模型。

- 本页用 ChatGPT、Claude、Gemini、千问和豆包作例子。它们不是同一个按钮的不同皮肤，而是不同公司、不同模型、不同工具接入和不同产品取向。
- 大模型通常更贵、更慢一些，但知识、写作、创意、复杂问题处理更强。
- 小模型更便宜、更快，但更可能遗漏细节、写作平庸、幻觉更多。

这里可以形成一个使用习惯：每次重要工作开始前，先看左上角模型名和模式开关。不要把弱模型的失败归因于“LLM 都不行”，也不要把强模型的回答当作无需验证的权威。

## 7. 思考模型：什么时候值得让模型多想一会儿

接下来讨论思考模型（thinking model）。前一讲已经说过，模型训练大体经历预训练、监督微调（supervised fine-tuning, SFT）和强化学习（reinforcement learning, RL）。强化学习让模型在大量类似教材练习题的问题上练习，特别是数学和代码问题。模型会尝试不同思路、回溯、检查假设、换角度，从而发现哪些“思考策略”能带来更好结果。

这些策略很难由人类标注员手工硬编码，因为我们并不知道什么样的思考过程最适合模型本身。强化学习让模型根据自己的知识和能力，试出对它有效的推理路径。这是相对新的训练阶段，各家 LLM 实验室近一年左右都在实验。DeepSeek 曾公开论文讨论通过强化学习激励 LLM 的推理能力。

在心理图像上，可以把原来的模型表情旁边加一个可选“思考气泡”。使用思考模型时，通常意味着模型经过额外的强化学习调优，会生成更多中间 token，在困难问题上提高准确率。代价是需要等待：模型可能花一分钟甚至几分钟，生成大量思考 token。对简单问题，如旅行目的地推荐，通常不值得等待；对数学、代码、复杂推理，往往有帮助。

一个具体编程例子是多层感知机（multi-layer perceptron, MLP）优化代码的梯度检查（gradient check）失败。把代码贴给 GPT-4o 这类旗舰普通模型，但不启用思考时，模型可能列出一些可能问题和调试建议，却没有找到真正 bug。随后切换到 OpenAI 的思考模型。OpenAI 当时名字不太直观，o1、o3-mini、o3-mini-high、o1 Pro mode 等以 `o` 开头的模型都属于思考模型，界面上会写 advanced reasoning、coding、logic 等说明。相同 prompt 给 o1 Pro 后，模型可能思考约一分钟，界面只展示思考摘要而不展示完整思维链，最后找到正确原因：参数打包和解包顺序不匹配，导致梯度检查失败。

同样问题也可以交给其他模型。Claude 3.5 Sonnet 虽然当时不是思考模型，却也能找到并解决问题；Anthropic 当时没有公开部署思考模型，但这种情况可能随时间改变。Gemini 也能解决，Grok 3 也能解决。Perplexity 托管 DeepSeek R1，能使用其推理能力；把问题贴过去后，可以展开看到一些原始思考内容，模型会说用户遇到梯度检查问题，检查参数打包顺序，发现梯度累积方式和参数顺序不一致，最后指出关键错误。Perplexity 的渲染界面未必适合所有人，但模型也能解决问题。

总结规则很直接：各家提供商可能有也可能没有思考模型。思考模型最适合困难数学、代码和多步推理。平常先试快速的非思考模型；如果回答明显不够好，或者问题本身很深、很难，再切到思考模型。Grok 之类产品会有 Think 开关，点开后底层切换到思考模型或让模型花更多时间。

### slide 6

本页把思考模型放在实际决策里，而不是神秘化。

- 思考模型不是“更有意识”，而是经过强化学习训练，更倾向于展开检查、回溯、验证、分解问题。
- 它的优势集中在数学、代码、逻辑、多约束规划等困难任务。任务越简单，收益越小。
- 它的成本是时间和 token。模型思考越久，用户等待越久，推理成本也越高。
- 普通强模型有时也能解决问题，例如 Claude 3.5 Sonnet 在梯度检查例子中就答对了，所以“思考模型”不是唯一答案。
- 最实用的策略是两步：先用快速模型得到初稿；如果不满意或问题关键，再切换思考模式。

这里的重点是“按任务开关能力”。不要把 Think 当作永远打开的高级按钮；它是给困难题用的慢速档。

## 8. 搜索工具：把最新网页放进工作记忆

到这里需要再次强调：默认语言模型只是一个闭合的压缩包，没有工具。接下来要给它最重要的工具之一：互联网搜索（internet search）。

可以用《白莲花度假村》第三季（White Lotus season 3）的例子说明搜索为什么必要。用户看完第一集，想知道第二集什么时候播出。传统方式是打开 Google，搜索“White Lotus season 3 new episodes”，再点开多个链接，忍受广告和混乱页面，寻找播出表。更理想的方式是：让模型替你搜索网页、访问页面、把网页内容放进上下文窗口，然后根据这些文本回答。

底层机制可以理解成：模型生成某个特殊的“搜索互联网”token，应用发现后暂停模型采样，拿模型给出的查询去搜索，访问网页，抽取页面文字，再把这些文字插入上下文窗口。搜索工具本身也在向上下文贡献 token，可能一次插入十个网页的数千 token。随后模型继续生成回答，此时它能直接引用上下文里的网页文本。对近期播出时间这类问题，没有搜索就几乎不可能可靠回答，因为这个信息可能是在模型预训练后才确定的，不在压缩包里。

Perplexity 早期就把这种 LLM 搜索做得很有说服力。ChatGPT 后来也加入了 Search the web 按钮。询问“White Lotus season 3 新集什么时候发布”时，Perplexity 会自己创建查询、访问网页、给出答案，并提供引用。引用很重要，因为用户可以点开网页核对，确认不是模型幻觉。

不同应用和不同模型的搜索接入差异很大。ChatGPT 有时会自动判断这是近期信息并搜索；如果用户明确知道这类问题需要搜索，也可以手动勾选 Search。Grok 也能自动搜索并回答。Claude 当时没有搜索集成，会说“截至我 2024 年 4 月的最后更新”，承认不知道最新播出时间。Gemini 2.0 Pro experimental 当时也没有实时搜索，回答没有官方日期；Gemini 2.0 Flash 则似乎有搜索能力，并给出来源和相关内容。Gemini 界面甚至说明 2.0 Pro experimental 缺少实时信息和部分 Gemini 功能。

所以，使用搜索工具时要看两件事：这个应用/模型是否接入搜索；模型是自动搜索，还是需要你明确点开或要求搜索。

常见搜索问题几乎都符合一个条件：答案可以通过 Google 搜索前几个结果得到，但模型参数未必可靠。

- 今天市场开不开？例如美国总统日时股市是否休市，搜索模型能理解“today”并搜索得出闭市。
- White Lotus 第三季在哪里拍摄？信息较新且有点小众，适合搜索。
- Vercel 是否提供 PostgreSQL 数据库？产品能力会变化，应该查最新资料。
- Apple 明天要发布什么，有哪些传闻？这是近期信息。
- Single's Inferno 第四季演员有哪些必须知道的信息？很新。
- Palantir 股票为什么上涨，市场热情来自哪里？
- Civilization 7 具体什么时候发布？
- Bryan Johnson 最近是否说过他用什么牙膏？这既小众又可能变化。
- 去越南旅行安全吗？安全情况可能变化。
- Twitter 上看到关于 USAID 的讨论，想知道大概发生了什么。这种“看到热点但缺少上下文”的问题，适合让搜索模型给出背景梗概。

### slide 7

本页把搜索理解为一种“上下文注入”机制。

- 搜索不是模型突然拥有了实时知识，而是应用帮模型把网页文本复制进上下文窗口。
- 对近期、变化快、小众、需要引用的问题，搜索应该优先于直接问。
- 模型可能自动判断要搜索，也可能需要用户明确点 Search 或写“请联网搜索”。
- 搜索结果仍然可能错：查询可能写偏，网页可能不可靠，抽取可能遗漏，模型引用也可能误读。
- 引用的意义不是装饰，而是让用户能回到来源验证。

在本课程语境下，更贴近的例子是“今年数学建模竞赛报名截止时间”“某门课程是否调课”“学院讲座在哪个教室”。这些答案不是模型参数里的长期知识，而是刚从网页或通知里搬进来的工作记忆。只要理解这一点，后面文件上传、深度研究和图片 OCR 就都容易理解了。

## 9. 深度研究：搜索加思考，生成一份初稿报告

深度研究（Deep Research）是一种重要但容易被低估的新能力。当时 ChatGPT 把 Deep Research 放在 Pro 层，约每月 200 美元。它大体可以理解为：互联网搜索加思考模型，再连续运行很久。模型会花十几分钟甚至更久，进行多轮搜索、阅读网页和论文、整理引用，然后生成一份长报告。ChatGPT 是最早公开宣布这种能力的公司之一，之后 Perplexity 也有 Deep Research，Grok 有 Deep Search。Grok 的 Deep Search 可能类似深度研究，但具体机制未必完全相同。

一个具体例子是 Bryan Johnson 的 Blueprint starter pack 里的 Longevity Mix。里面有很多 health actives；看到 Ca-AKG 之类成分时，用户可能不知道“boost energy production for sustained vitality”这种营销语到底是什么意思。传统方式是自己 Google、读 Wikipedia 或论文；Deep Research 则可以替你处理一批资料。

一个可用 prompt 大意是：Ca-AKG 是 Bryan Johnson Blueprint 中 Longevity Mix 的一种健康活性成分，每份 2.5 克。请研究 Ca-AKG，解释它为什么可能出现在 Longevity Mix 里，它在人类或动物模型中的可能功效、潜在作用机制，以及潜在担忧、毒性等。开启 Deep Research 后，模型有时会先问澄清问题，例如关注人类临床研究还是动物模型，是否需要比较其他长寿化合物。可以回答两者都看、所有来源都可以、无需比较其他化合物、可以简洁。随后模型开始研究。

研究过程中，模型会多次搜索、阅读论文和网页，积累巨大的上下文窗口，并处理这些资料。Grok 界面会显示它正在查论文、WebMD 等来源，逐渐组织“Ca-AKG 是什么，为什么在 Longevity Mix 中，如何与长寿相关”等要点。这不是简单短回答，而像是为任意主题生成一篇定制研究报告。报告会带引用，用户可以继续深入阅读。

最终 Perplexity 和 ChatGPT 都能完成报告。ChatGPT 可能花约 5 分钟，看 27 个来源，报告讨论蠕虫、果蝇、小鼠、人类临床试验进展、提出的作用机制、安全和潜在担忧，并附参考资料。在一些使用体验中，ChatGPT 的版本更彻底、更长、读起来更合理；Perplexity 和 Grok 的报告可能更短、更简略。

但 Deep Research 不是事实保证。即使它在研究、引用、阅读资料，也可能幻觉、编造、误解论文。因此要把它当作第一稿、资料入口和论文清单，而不是最终结论。正确用法是打开引用论文，检查模型是否理解正确，再继续追问。

Deep Research 还有几个典型用例。第一，比较 Brave 和 Arc 浏览器的隐私性，整理报告并查看来源后，可以帮助用户判断 Brave 是否在隐私上显著更好。第二，研究小鼠寿命延长，了解不同实验室如何用各种技术延长小鼠寿命，因为小鼠是长寿研究的动物模型。第三，研究美国 LLM lab 的规模和融资情况，生成表格。但这个例子也可能失败：有些数字看起来不离谱，有些像是错的；xAI 缺失是重大遗漏；Hugging Face 可能不该算作美国主要 LLM lab；EleutherAI 由于资源规模也不太符合。结论仍然是：很有用，但必须当第一稿。

### slide 8

本页把 Deep Research 和普通搜索区分开。对数学学院大三阶段的学习任务，可以使用“统计学习和最优化两个方向该怎么选”“数学建模竞赛某个题目有哪些文献入口”“暑期科研项目需要哪些先修课”等例子。

- 普通搜索适合“答案在前几个链接里”的问题；Deep Research 适合需要多来源综合、比较、引用、长报告的问题。
- Deep Research 会持续多轮搜索和阅读，所以耗时更久，也更适合方向比较、文献初筛、课程/竞赛资料综述、复杂背景研究。
- 它的输出像定制研究报告，但仍然不是审稿过的论文，也不是事实保证。
- 引用要被当作入口：报告帮你找到该读哪些资料，但最终判断仍要回到来源。
- 失败例子很重要：美国 LLM lab 表格漏掉 xAI、混入 Hugging Face 和 EleutherAI，说明再高级的研究模式也会遗漏或误分类。

Deep Research 的价值是“把无序网页变成有组织的研究入口”，不是“替你完成所有判断”。越是高风险或专业领域，越要从报告回到原始文献。

## 10. 文件上传：把具体文档放进上下文

搜索和 Deep Research 都是在帮模型获取外部文档。用户也可以自己上传文件。这样模型就不用只靠参数里的模糊知识，而能直接参考上下文里的具体材料。

可以用 Claude 3.7 举例。Claude 3.7 刚发布时，被认为是当时新的 state-of-the-art 模型，并且 Claude 也有 thinking mode。普通模式是 normal，extended 模式标注为适合数学和代码挑战。虽然界面未明说，但它很可能也经过类似强化学习训练。

可以上传一篇 Arc Institute 的论文，内容是一个训练在 DNA 上的语言模型。即便用户不是生物专业，只要对这篇“genome modeling and design across all domains of life”、Evo 2 这类生物基础模型感兴趣，也可以把 PDF 放入上下文，然后和模型一起读论文。这是 LLM 非常适合的场景。

上传方式很简单，拖放 PDF。例子中的 PDF 约 30MB。需要注意：应用在处理 PDF 时，很可能丢弃大量图片，或者即使保留图片也不一定像人一样理解。实际底层常常是把 PDF 转成文本，再把文本放进 token 窗口。放进窗口后，它就成了工作记忆，可以提问。通常可以先问：“请总结这篇论文。”如果在 Claude 中遇到长度限制，也可以转到 ChatGPT，用 GPT-4o 且不启用思考模式先读摘要。模型总结论文时，会概括 Evo 2 大规模生物基础模型及关键特性。随后可以边读摘要和引言，边向模型追问。

同样方法也适合读书。一个例子是 Adam Smith 1776 年的《国富论》（The Wealth of Nations），经典经济学基础著作。它很早，但很多洞见今天仍然有现代意义。因为它是 1776 年作品，可以从 Project Gutenberg 找到原文。可以找到正在读的章节，例如第一卷第三章，讨论劳动分工如何受市场范围限制。大意是：市场太小，人们就不能充分专业化；专业化对财富创造很重要，因为专家可以专注于小任务；但只有市场足够大，专业化产出才有地方销售。

可以把章节复制到 Claude，并说明“我们正在读《国富论》，请先总结这一章”。Claude 复制大段文本时，界面会把它显示为文本附件，而不是完全塞在输入框里。通常先要一份概要，然后开始读原文，遇到问题随时问。和 LLM 一起读书可以显著提高理解和记忆，尤其适合跨领域文档，比如生物学论文，或者很久以前写的文本，比如 1776 年的经济学、莎士比亚等。LLM 让阅读更容易接近，因为你不会一开始就被语言和背景卡住，而可以慢慢一起拆解。

现在相关工具仍然有些笨拙。用户可能需要在书籍网页和聊天界面之间复制粘贴，非常不顺手。理想体验应该是读书时直接高亮段落并提问，但这类工具未必已经做得足够好。尽管如此，一个重要建议是：不要独自读难材料。

### slide 9

本页继续沿用“工作记忆”框架：文件上传就是把你关心的具体材料放到模型眼前。

- 模型可能“知道”《国富论》，但不一定精确记得某一章的每个论证；上传原文比凭记忆问可靠。
- PDF 上传通常会经历文本抽取，图片、表格、排版可能丢失或被误读，所以关键数据要核对。
- 阅读论文时，可以先要摘要，再围绕 abstract、introduction、figures、method 一段段追问。
- 阅读古典文本或跨领域材料时，LLM 的作用像一个随叫随到的助教，帮你解释背景、术语和论证结构。
- 目前体验可能笨拙，但价值很高：把原文给模型，再让模型基于原文解释，而不是凭模糊记忆讲。

使用 LLM 做阅读助手时，要同时保留一个边界：模型是否真的看到了图、表、公式，不能想当然。重要内容最好让模型先转写出来，用户确认后再追问。

## 11. Python 解释器和高级数据分析：把精确计算交给程序

另一个强力工具是让 LLM 使用 Python 解释器（Python interpreter）或编程语言。此时模型不是直接给答案，而是写程序，通过特殊 token 告诉应用“下面不是给人看的文字，而是请运行的代码”。应用暂停模型采样，执行程序，把运行结果作为文本返回给模型，模型再继续向用户解释。

最简单例子是乘法。问 `30 * 9`，模型可以直接回答 270。这种简单算术像记忆或心算，不需要工具。但如果给出很大的乘法，人类会找计算器，LLM 也应该找工具。ChatGPT 被训练为能识别哪些问题不该“脑算”，而应使用代码解释器。此时它会打开 Python interpreter，写程序计算，执行后把结果交回模型。

不同 LLM 的工具能力不一样。ChatGPT 能用 Python，所以大乘法答对。Grok 3 当时似乎没有 Python 解释器，会在“脑中”算，结果非常接近但错了：某一位应该是 120，它给成了 060。Claude 在例子中写了 JavaScript，也能得到正确结果。Gemini 2.0 Pro 第一次没有显示工具却给出看似正确的大乘法；继续换更难的题后，Gemini 就算错了。结论是：如果模型没有工具或不愿意用工具，它可能尽力而为，并幻觉一个很接近但错误的答案。用户必须知道当前应用是否有可执行代码工具。

高级数据分析（Advanced Data Analysis）是 ChatGPT 中将 LLM 和 Python、图表、文件结合的能力。它可以被看作一个初级数据分析师。示例流程可以是：先要求 ChatGPT 使用搜索工具研究 OpenAI 估值，整理每年估值表。之所以明确要求搜索，是因为估值数据不应该由模型幻觉出来。然后要求“用对数尺度画 y 轴”。ChatGPT 写程序，生成图表并展示出来。这对于收集数据、上传电子表格、快速可视化非常有用。

但例子也展示了危险。表里 2015 年估值未知，ChatGPT 写代码时可能悄悄把 2015 填成 0.1，也就是假设为 1 亿美元，没有明确告诉用户。之后如果要求拟合趋势线并外推到 2030 年，模型可能用 SciPy 的 `curve_fit` 做指数拟合，生成图表，并声称 2030 年估值约 1.7 万亿美元。仔细看图时可能发现不一致：图上 2030 的标记像是 2027.1B，也就是约 20 万亿美元级别，而不是 1.7 万亿美元。要求直接打印变量后，结果确实可能显示 2030 年趋势外推约为 20 万亿美元。模型会承认自己搞错。

这个例子说明两点：工具非常强，能写代码、画图、拟合、展示结果；但模型像一个有点粗心的初级分析师，会做隐含假设，也会错误解释自己的代码输出。懂代码的人应该读代码、查变量、核对图表。如果用户完全不能检查，使用这类工具要非常谨慎。

### slide 10

本页的重点是：精确任务应该交给可执行工具，但工具链仍然需要监督。对数学学习来说，例子可以是矩阵运算、数值积分、Monte Carlo 模拟、误差收敛图、作业成绩表或实验报告里的拟合曲线。

- 简单算术模型可能直接答；复杂乘法、矩阵计算、统计、图表、字符串处理，最好让模型写代码运行。
- 工具调用的本质是：模型写程序，应用执行，结果回到上下文，模型再解释。
- 不同应用工具不同。没有 Python 或 JavaScript 执行能力的模型，可能会“脑算”并给出接近但错误的结果。
- Advanced Data Analysis 很适合上传表格、清洗数据、画图、拟合趋势、生成可视化初稿，也适合快速检查数值分析实验的误差阶。
- 风险在于隐含假设和解释错误：例如把缺失成绩当作 0，把未知量随手填上，或者把图表变量解释错。

可以把 ChatGPT 比作“会写代码但需要 code review 的初级分析师”。使用者要学会看它写了什么、运行了什么、变量是什么，而不是只看最后自然语言结论。

## 12. Claude Artifacts：让模型直接写小应用和图

Claude 的 Artifacts 是另一个代码相关功能。可以先让 Claude 根据 Adam Smith 的 Wikipedia 介绍生成 20 张 flashcard。例如 Adam Smith 何时受洗、何时去世、国籍是什么等。生成卡片后，继续要求：“现在使用 Artifacts 功能写一个 flashcards app 来测试这些卡片。”

Claude 随后写出 React 代码：用 React 组件硬编码这些问答，实现翻卡、判断答对答错、重置进度、打乱卡片等功能。Claude 界面能直接在浏览器中加载这些 React 组件，于是用户得到一个为自己这一次任务定制的小应用。传统软件模式是工程师写一个通用 app，用户再导入卡片；Artifacts 展示的是新范式：LLM 直接为你的材料写一个本地浏览器 app。

这类 app 通常没有数据库、没有完整后端，不是互联网上那些大型应用；它们是能在浏览器本地运行的小工具。它们有时可以相当复杂和有用。很多人会分享各种 artifacts，例如计时器、小游戏等。

Artifacts 的一个常用场景是图示生成，尤其是概念图。回到《国富论》第一卷第三章，可以告诉 Claude：我们正在读 Adam Smith 的《国富论》，附上第一卷第三章，请创建这一章的概念图。Claude 往往会写 Mermaid 图（Mermaid 是一种用文本定义流程图/关系图的库），把章节论证整理成树状结构：核心原则是劳动分工受市场规模限制；章节包括贸易例子、陆路和水路运输比较、地理因素的重要性、早期文明如何因为水路运输而发展，从而支持专业化。

对偏视觉思维的学习者来说，把信息排成树状图能帮助记住章节讲什么，也能看出论证如何空间化组织。书、章节、源代码，几乎任何东西都可以让模型生成概念图。

### slide 11

本页把 Artifacts 理解为“模型不只写文本，也可以写可运行界面”。数学学习中的例子可以是实变函数复习卡片、随机过程知识结构图、数学建模方案流程图，或者一个小型公式训练器。

- Flashcards app 的例子说明：模型可以把一次性材料直接变成本地浏览器工具，而不是只输出一段回答。比如把“Cauchy 列、紧致性、连续函数性质”做成自测卡片。
- Artifacts 里的小应用通常没有数据库和后端，所以适合局部、个人、一次性或轻量任务。
- Mermaid 图是非常实用的 artifacts：用少量代码把章节、论文、代码库、证明结构、概率论知识树整理成结构图。
- 对视觉学习者来说，图示能暴露论证结构：核心命题、支撑例子、对比关系、因果链条。
- 这类能力和 Advanced Data Analysis 相似：模型写代码，产品负责在界面中运行或渲染。

这里体现了一个范式变化：过去我们问模型“请解释给我听”；现在可以问“请为这个材料做一个能交互的小工具或图示”。它不是替代软件工程，但能显著降低一次性工具的成本。

## 13. Cursor 和 vibe coding：专业编程要把模型放进代码库

在真实编程工作中，并不应该总去 ChatGPT 网页里要代码片段。原因是网页聊天没有足够代码库上下文，复制粘贴也太慢。专业编程更适合使用能直接读写本地文件的应用，例如 VS Code、Windsurf、Cursor 等。

Cursor 是安装在 MacBook 上的本地程序，不是网页。它能访问电脑上的项目文件，并和这些文件一起工作。底层它可能调用 Anthropic 的 Claude API，例如 Claude 3.7 Sonnet，但用户不需要手动打开 Claude 网页、复制代码片段。Cursor 会自动把目录文件、当前代码、相关上下文交给模型。

一个简单例子是 React 井字棋（Tic Tac Toe）应用。用户可以从全新项目开始，在 Cursor 的 Composer 功能里写几句话：设置一个新的 React 仓库，删除模板代码，做一个简单井字棋 app。Cursor 几乎在一分钟内完成 CSS、JavaScript/TypeScript 等文件修改，用户本地运行后能在浏览器里玩，X 可以赢，也可以平局。

这些工具的发展路径也很清楚。早期有 Command K：选中一行或一段代码，让模型改。后来有 Command L：解释这段代码。底层都是调用同样的模型 API，但编辑器应用能自动提供文件上下文。现在发展到 Command I/Composer，尤其是带 agent 集成的 Composer，更像代码库上的自主代理：它能执行命令、跨文件编辑、安装依赖、修改样式。用户主要坐在旁边发指令。

这种方式常被称为 vibe coding：把控制权交给 Composer，只告诉它想要什么，然后希望它能工作。最坏情况仍然可以回到传统编程，因为所有文件都在本地，程序员可以打开 CSS、TypeScript 等任意修改。

例如要求井字棋在 X 或 O 获胜时加入 confetti。Composer 可能决定安装 `react-confetti`，用户确认后它安装依赖，修改 `App.tsx`，加入 confetti 组件和胜利格子的 CSS。它还可能尝试加入胜利音效，这时用户需要判断音频文件从哪里来。Composer 会暂停等待确认命令，例如创建 `public/sounds` 目录，下载或引用 `victory.mp3`，并加入 fallback。每次保存文件，本地开发服务器都会更新。最终胜利时可能出现 confetti 和音乐；声音文件 URL 可能来自模型在训练数据中见过的公开仓库。最后可以 accept all，并继续开发；如果调不通，随时回到人工编程。

### slide 12

本页讲专业编程场景下的关键迁移：不要把代码助手关在聊天框里。对数学大三阶段的学习任务，最自然的例子不是做井字棋，而是数值分析、优化、统计学习或数学建模课程项目。

- ChatGPT 网页适合问概念、要小片段、讨论思路；真实项目需要文件上下文、依赖、命令、跨文件修改，例如同时修改 `solver.py`、`plot_error.py` 和 `report.tex`。
- Cursor、Windsurf、VS Code 插件等工具把模型放进代码库，底层仍调用 LLM API，但上下文和操作权限更适合编程。
- Composer/agent 能执行命令、安装包、改多个文件、运行项目，是从“代码补全”走向“代码库代理”。
- Vibe coding 的优势是速度：几句话生成一个可跑实验、误差图或报告模板，再快速迭代。
- 风险也很明显：模型可能下载未知资源、做你没完全看懂的修改，所以要确认命令、审查 diff、知道如何回到传统编程。

AI 编程不是“不会编程也能完全放心”，而是“会编程的人获得一个很快的初级协作伙伴”。越懂工程，越能用好它；越不懂工程，越要谨慎接受它的修改。

## 14. 语音输入：先从“假音频”开始减少打字

前面所有例子主要是文本输入、文本输出。接下来讨论不同模态（modality）：人类更自然的格式包括语音、音频、图片、视频。日常使用中，键盘输入和直接说话都很常见；在手机上语音比例可能更高，因为手机打字更麻烦。

ChatGPT 手机应用里有两个容易混淆的语音按钮：一个是麦克风图标，一个是音频/语音模式图标。麦克风图标负责语音转文字（speech-to-text）：应用听你的声音，把它转写成文本，然后你再发送。比如打开手机 app、新建对话、按麦克风，说“为什么天空是蓝的？是因为反射海洋吗？”应用把音频转成文本，用户点击发送，模型按文本回答。

桌面端稍复杂。ChatGPT 桌面应用有 voice mode 图标，但没有单独的麦克风转写按钮。可以使用系统级转写工具，例如 Superwhisper、Whisper Flow、MacWhisper 等。例如将 Superwhisper 绑定到 F5：按 F5 开始听，说完再按 F5，应用把语音转写到当前输入位置。这样可以在任何应用里语音输入，不限于 ChatGPT。简单日常问题可以直接说；如果涉及产品名、库名、专有名称，转写容易错，应该改用打字确保准确。

输出侧也有文本转语音（text-to-speech）。ChatGPT 回答旁边可能有 Read aloud 按钮，点击后系统把文本交给另一个模型读出来。不同应用如 ChatGPT、Claude、Gemini 是否支持朗读不一定相同。也可以下载系统级 text-to-speech 工具，在任何应用里朗读。

这类能力可以称为“假音频”：我们仍然通过文本和 LLM 交互，只是用 speech-to-text 把输入前处理成文本，用 text-to-speech 把输出后处理成音频。LLM 本身处理的仍然是文本 token。即便如此，也很值得多用语音，因为它足够好，能大幅减少打字。

### slide 13

本页先讲最实用的语音用法：不用把它想复杂，先用它少打字。

- 麦克风转写是 speech-to-text：你说话，系统转成文字，LLM 仍然读文本。
- Read aloud 是 text-to-speech：LLM 写出文字，另一个模型把文字读出来。
- 手机端语音输入尤其省事；桌面端可以用 Superwhisper 这类系统级工具，把语音输入带到任何应用。
- 专有名词、代码库名、包名、变量名容易转写错，重要时要手动检查。
- 这种“假音频”虽然不是模型原生听说，但已经足够改变工作流：很多短问题说出来比打出来快得多。

先掌握低门槛收益：能说就别打，但说完要看一眼转写。语音输入不是炫技功能，而是每天都能节省时间的接口。

## 15. 原生音频、Grok 语音和 NotebookLM 播客

真正的音频能力不是把声音先转文字，而是让语言模型原生处理音频 token。文本可以被切成 token，音频也可以被切片。常见做法是把音频转换成频谱图（spectrogram），观察不同频率在时间上的能量，再按小窗口量化成 token。可以有一个包含十万个音频片段的词表，让模型学习理解和预测这些音频 chunk。这样模型能直接听和说，而不是通过文本中转。

ChatGPT 的 Advanced Voice Mode 就是这类“真音频”的例子。它让语音在语言模型内部原生处理：模型能理解音频片段并预测音频片段，直接听、直接说，中间不需要文本。用户可以先问候模型，然后问为什么天空是蓝色，是否因为反射海洋；模型会回答瑞利散射（Rayleigh scattering）。用户也可以要求不要普通说话，而用 Yoda 的声音、像智慧导师一样讲；模型会改变风格。再要求像海盗一样讲，模型也会用海盗口吻解释。还可以要求它讲一个小女孩发现天空蓝色不是因为反射海洋的故事，随后打断让它快速从 1 数到 10、再更快数到 20。之后询问牛怎么叫，模型可能说 moo；问狐狸怎么叫，模型可能解释狐狸会 bark、scream、yip；要求模仿狐狸时，模型可能拒绝说自己不能发动物声音。即使它刚刚发过牛叫，也可能仍然拒绝模仿狐狸。

对话结束后，ChatGPT 会给出文字转写，但文字只是音频对话之后的 transcript。真正交互时是音频 token 往返，不是文本参与。Advanced Voice 很酷，但也可能过度谨慎，经常拒绝，令人尴尬或烦人。功能和价格层级变化很快，Advanced Voice 也可能逐步向免费用户开放，所以要随时查看当前产品层级。

Grok 手机 app 也提供类似高级语音模式，桌面网页不一定有。Grok 的特点之一是模式多、娱乐性强；OpenAI 更谨慎、更容易拒绝，而 Grok 更愿意“放开”。它包含 default、Romantic、Unhinged、Conspiracy、Sexy 等模式。Romantic 模式会用暧昧口吻说一直仰慕用户；Unhinged 模式会用很冲的语气调侃；Conspiracy 模式会顺着“Trudeau 是 Castro 的儿子”之类阴谋话题扩展到 Illuminati、影子政府、蜥蜴人、女王是机器人等；Sexy 模式可能快速进入带有性暗示的场景，应立即停止。这说明不同产品在语音人格、安全边界和娱乐取向上差异很大。

另一种音频交互范式是 Google 的 NotebookLM。它不是和模型实时语音聊天，而是让用户上传资料，然后生成按需播客。NotebookLM 左侧可以上传 raw text、网页、PDF 等来源。上传 Arc Institute 关于基因序列基础模型的 PDF 后，资料进入上下文，用户可以聊天提问；右侧还有 Deep Dive podcast 的生成按钮。点击后等待几分钟，它会根据资料生成一个约 30 分钟的定制播客。生成的两个声音可以讨论理解 DNA 的 AI，不只是读取 DNA，还能预测变化如何影响蛋白质乃至整个生物，并介绍 Evo 2 和 OpenGenome 2 之类数据集。

NotebookLM 播客可以自定义说明、重新生成，也有 interactive mode，用户可以在播客播放时插入问题。它尤其适合对某个文档、论文、主题有被动兴趣，准备散步或长途开车时使用。它适合那些太小众、没有人类播客覆盖的话题。也可以生成一个完整播客季，例如 Histories of Mysteries 这样的主题系列，并上传到 Spotify。想了解工具效果，可以去听这类生成播客，再自己上传资料试。

### slide 14

本页把三种音频能力分开，避免混在一起。

- 假音频：speech-to-text 和 text-to-speech，模型仍然读写文本。
- 真音频：Advanced Voice 这类能力，模型直接处理音频 token，可以听语气、变声音、实时打断、生成语音。
- 音频产品体验差异很大：ChatGPT 更谨慎，Grok 更娱乐化，安全边界和人格模式不同。
- NotebookLM 是另一类：不是实时对话，而是把上传资料转成定制播客，适合散步、开车、被动了解小众主题。
- 所有这些能力背后仍然可以回到 token：文本 token、音频 token、上下文窗口和产品层工具。

“音频不是一个功能”。它包括转写、朗读、原生语音对话、资料播客等不同层级。使用前要问：我只是想少打字，还是想让模型真的听和说，还是想把资料变成可听内容？

## 16. 图片输入、图片生成、视频理解和视频生成

图片也可以表示成 token 流。最简单的想法是把图片切成矩形网格 patch，把每个 patch 量化到一个包含十万个可能 patch 的词表中。图片就变成 patch token 序列，可以放进上下文窗口，也可以和文本、音频一起训练。Transformer 本身并不知道某些 token 是文本、某些是音频、某些是图片；它只是在建模 token 流的统计模式。只有编码器和解码器知道如何把图片编码成 token，再把 token 解码回图片。

图片输入有多种典型用法。第一个例子是 Brian Johnson Longevity Mix 的营养标签。用户如果不认识许多成分，想知道它们是什么、为什么在配方里，最好先让模型把图片中的相关信息转写成文本，因为不能默认模型一定看对了。模型把内容放进表格后，用户可以检查数值是否正确，再基于文本追问。然后可以让模型把成分分组，并按可能安全程度排序，区分哪些像普通复合维生素成分，哪些更可疑、更奇怪、研究更少。这可以帮助形成后续研究的第一稿。

第二个例子是血液检测结果。如果有约 20 页 PDF，直接看很难用，可以先上传 lipid panel 等小截图，确认 ChatGPT 正确读取数值，再让它解释；随后逐块上传整个血检结果。这里有两点提醒：第一，要核对转写是否正确；第二，在 MacBook 上可以用 Control + Shift + Command + 4 截图到剪贴板，然后在 ChatGPT 中 Command+V 粘贴，快速对屏幕任意部分提问。血检是医疗信息，不能错；ChatGPT 的初步解释可以作为一稿和问医生的问题清单，原因是血检结果不是冷门知识，网上有大量文档，模型应该懂常见范围和数值意义。但最终仍应和医生讨论。

第三个例子是数学和代码。看到论文里的 tricky expression，可以截图后先让模型转成文本，这样可以复制文本再问模型，例如某个表达式在 `x = pi` 时取值如何。这是一个 trick question，用户可以自己试。第四个例子是 Colgate 牙膏成分。如果对牙膏里的成分有疑问，可以让模型转写并解释，随后问哪些最安全、哪些最不安全；如果只关心牙膏功能，不关心颜色等无用东西，哪些可以去掉。模型会区分必要功能性成分和许多可能不必要的添加物，这也能帮助用户识别食品和化妆品中哪些成分更像装饰性添加。第五个例子是解释 meme。有人不懂一张乌鸦梗图时，可以把图贴给 ChatGPT，模型可能解释：一群乌鸦叫 murder，所以一只乌鸦接近另一只乌鸦就像 attempted murder。ChatGPT 对这类视觉笑话也可能解释得很好。

反过来，模型也可以生成图片。OpenAI 的图像生成产品叫 DALL·E，第三版已经能根据任意 prompt 生成很漂亮、风格化的图片，例如京都某寺庙风格图。图片生成主要适合任意内容创作、图标和 YouTube 封面。例如 YouTube 频道中“Let's reproduce GPT-2”等内容的封面图，可以用 Ideogram 等 DALL·E 竞争工具生成，有些也可能来自 ChatGPT。工具可以互换使用。

需要注意，DALL·E 3 当前并不是由主语言模型完全原生输出图片。ChatGPT 接到“生成一张总结今天的图片”时，通常先根据上下文生成一个图片 caption，再把 caption 发送给单独的图像生成模型。这是产品层缝合起来的能力，而不是主 LLM 自己直接生成像素。不过对普通使用者，不必过分纠结。

视频理解是图片理解的延伸。ChatGPT 的 Advanced Voice 在手机 app 中有视频能力，网页端不一定有。用户打开高级语音并启用摄像头，可以向模型展示墙上的黑色声学泡棉，模型识别出 acoustic foam panel，并询问是否测试减弱回声；如果用户说明测试效果不太有用，模型可能建议摆放位置和角落覆盖可能影响效果。接着展示书，模型可以识别 Jack Weatherford 的《Genghis Khan and the Making of the Modern World》、Richard Feynman 的《Surely You're Joking, Mr. Feynman!》，也可以识别 Aranet 4 便携 CO2 监测仪，说明它测二氧化碳、温度、湿度和气压。读到 713 ppm 时，模型可能说明室内一般还可以，理想低于 800 ppm，高于 1000 ppm 可能需要通风。展示地图时，模型可能识别为 J.R.R. Tolkien《The Lord of the Rings》中的 Middle-earth 地图。

这个体验很自然，适合向不熟悉 AI 工具的人展示：他们可以直接拿摄像头指着东西问。但对重度文字/代码用户来说，日常查询往往更有目标，未必需要频繁使用摄像头。底层模型是否真的连续消费视频并不总是清楚，可能只是每秒取一张图像帧；但从用户角度，感觉像在流式视频对话。

最后是视频生成。现在有很多 AI 视频生成工具，发展很快。这个能力相对自解释：输入文字或图像提示，输出短视频。一个常见比较方式是让多种 AI 视频模型生成同一主题，例如丛林老虎，然后比较风格和质量。不同模型都有不同风格和质量；某些模型接近 state-of-the-art，也出现 OpenAI Sora 等工具。用户可以比较并使用专门的视频生成工具。

### slide 15

本页把视觉相关能力分成输入和输出。

- 图片输入：模型读板书、课件截图、教材公式、论文图表、宿舍或学院通知。关键是先让它转写或描述，再由人确认是否看对。
- 图片生成：模型或产品根据 prompt 生成图像，适合课程汇报封面、社团海报、数学建模展示图标和创意素材。
- 视频理解：移动端摄像头让模型识别书本、仪器读数、教室白板、地图和环境；底层可能是连续视频，也可能是抽帧。
- 视频生成：专门模型从文字生成短视频，可用于社团宣传或课程展示素材，但工具变化很快，内容仍要核对。
- 多模态的统一抽象仍然是 token：文本、图像、音频、视频都可以被编码成 token 流，再进入上下文。

多模态越强，越要核对输入是否被正确看见。尤其是医学、数字、标签、公式和仪器读数，先转写确认，再让模型解释。

## 17. 记忆、自定义指令和跨对话个性化

最后一组功能是生活质量（quality of life）功能。第一是 ChatGPT 的记忆（memory）。普通对话中，每个新对话从空上下文开始；点 New Chat 后，当前 token 窗口清空。但 ChatGPT 还有跨对话保存信息的能力。

一个记忆例子是询问 ChatGPT 大约什么时候是 Hollywood peak。模型没有像很多模型那样说“我只是 AI，没有观点”，而是给出判断：最后一个被 franchise 接管前的高峰大约是 1990 年代到 2000 年代初。如果用户同意并明确要求模型记住这个偏好，界面会出现 memory updated，记录用户认为 1990 年代末和 2000 年代初是 Hollywood 的伟大高峰等信息。

记忆库可以理解成 ChatGPT 的一个关于用户的数据库。模型把对用户的了解写成小摘要字符串，保存到 memory bank。之后这些记忆会被预先插入到所有对话前面，让模型能访问。自然使用 ChatGPT 一段时间后，它会逐渐知道你的一些偏好，并在回答中引用这些信息，使回答更相关。有时模型会自动触发记忆更新，有时需要用户明确说“请记住这个偏好”。

这本质上就是一个文本字符串数据库，用户可以编辑、添加、删除和管理。记忆功能当时相对独特，其他 LLM 未必有。比如 ChatGPT 很擅长电影推荐，把“喜欢 1990 年代末到 2000 年代初 Hollywood”记住后，未来电影推荐可能更贴合用户。

第二是自定义指令（Custom Instructions）。用户可以在 settings 中 customize ChatGPT，告诉它“应该有什么 traits”。例如可以写“不要像 HR business partner 一样说话，正常和我说话；尽可能给解释、教育和洞见”。也可以在身份信息里做实验，例如说明自己正在学韩语，希望模型给韩语时使用某种默认正式程度，避免过于随便或过于正式。凡是想跨对话全局修改 ChatGPT 说话方式和默认行为的内容，都可以放进 custom instructions。许多其他 LLM 应用也有类似设置，应在 settings 中寻找。

### slide 16

本页解释记忆和自定义指令的区别。

- 上下文窗口是当前对话的短期工作记忆；New Chat 会清掉它。
- Memory 是跨对话的用户资料数据库，保存的是关于用户的短摘要，并在新对话中预先提供给模型。可以让它记住“我更喜欢严格定义 + 例子 + 反例”“我正在补概率论基础”这类长期偏好。
- Custom instructions 是用户主动写的全局行为设定，告诉模型偏好语气、解释风格、身份背景、默认格式等。例如要求解释数学概念时先给直觉，再给定义，最后给一个可计算例子。
- 记忆会让模型逐渐个性化，但也带来隐私和偏见问题，所以要定期管理、删除不想保留的内容。
- 自定义指令适合长期偏好，不适合每个任务都不同的临时要求；临时要求仍应写在当前 prompt 里。

这里可以分成三层：当前 prompt 控制当前任务，custom instructions 控制长期风格，memory 提供关于用户的长期背景。三者都通过上下文影响模型，而不是给模型一个神秘的“自我”。

## 18. 自定义 GPT：把可复用 prompt 固化成小工具

最后一个功能是自定义 GPT（custom GPTs）。它适合经常重复的固定工作流，语言学习是一个典型场景。

第一个例子是韩语词汇提取器（Korean vocabulary extractor）。给它一句韩语，GPT 提取词汇的字典形态，并按 `Korean; English` 格式输出，方便复制到 Anki 之类 flashcards app。打开 edit GPT 可以看到，这没有什么神秘能力，主要就是 instructions。可以写背景：自己是韩语初学者；写任务：给一段文本，提取词汇；再给若干输出示例。给 LLM 写指令时，除了描述任务，还应该给具体示例。只描述任务是零样本提示（zero-shot prompt）；给几个例子就是少样本提示（few-shot prompt）。few-shot 通常能显著提高准确率。

保存这个 custom GPT 后，每次只要给一句新韩语，它就执行同样任务。它真正节省的是 prompt 时间：不用每次从头描述背景、格式和要求。只要某个 prompt 经常复用，就可以保存成 custom GPT。

第二个例子是详细韩语翻译器（Korean detailed translator）。很多人会用 Google Translate，但 Google Translate 对韩语常不够好；有人用 Naver Papago 等。普通翻译可以给出译文，但学习者不一定看懂句子如何对应到译文，尤其是颗粒度、助词、语气等常被省略。可以做一个 custom GPT：先翻译整句，再逐词逐片段详细拆解。例句翻译成“现在是下午 3 点，我想去我最喜欢的咖啡馆”，并逐部分解释 `chigan`、afternoon 等含义。好处是可以继续追问澄清问题。这比普通翻译器更适合语言学习，因为它懂细微语义、俚语和语气。

这个 custom GPT 的 instructions 也可以采用 few-shot prompt。说明可以写成：你会得到一个韩语句子，先把整句翻成英文，再详细拆分整句。用类似 XML 的标签组织示例，例如 `<example1>` 开始、结束，里面有 input 和 desired output。这样模型更清楚示例边界。这和教人类很像：只用语言解释任务不如给例子，人类也能通过少量例子更快学习任务。

第三个例子把图片 OCR、翻译和拆解结合起来。看韩语内容时，字幕嵌在视频像素里，无法直接复制文本。于是可以截图，例如 Single's Inferno 中 Jinyoung 和 Seulki 的一幕，把图片贴给名为 Korean cap 的 custom GPT。这个 GPT 先 OCR（optical character recognition，光学字符识别）字幕，再翻译，再拆解。它的 instructions 可以说明：你会收到一个电视节目截图，显示一小段对话；先 OCR，再翻译，再 breakdown，并按喜欢的格式输出。之后看剧时，遇到需要帮助的字幕就截图粘贴，让 custom GPT 处理。

创建 custom GPT 的方式是在 ChatGPT 里进入 My GPTs，点击 Create a GPT，配置 instructions 等。GPTs 当时比较像 ChatGPT 的独有功能，但其他 LLM 应用可能有类似 project settings 或自定义助手能力，值得寻找。

### slide 17

本页把 custom GPT 理解为“保存下来的 prompt 模板”。对数学学习来说，custom GPT 可以是术语卡片生成器、英文教材逐句翻译器、板书 OCR 到 LaTeX 工具、错题拆解助手。

- Custom GPT 不是一定有新模型，很多时候只是把 instructions、示例、格式要求、背景信息保存起来。
- 适合高频重复任务：英文数学术语卡片、论文段落翻译、OCR 后转 LaTeX、固定格式摘要、证明检查清单、代码审查清单等。
- Few-shot prompt 是关键技巧：不仅告诉模型做什么，还给它几个输入和理想输出。
- XML-like 标签能帮助组织长示例，让模型分清示例边界、输入和输出。
- 多模态 custom GPT 可以组合能力：板书截图 OCR、LaTeX 转写、公式解释、推导步骤拆解，一次完成学习 workflow。

提示词也应被当成可维护资产。反复复制同一段 prompt，本质上就是在手动调用一个没有封装的工具；custom GPT 则把它封装起来。

## 19. 总结：在快速变化的 LLM 生态里做选择

LLM 应用生态正在快速增长、变化和繁荣。ChatGPT 是最早的大众产品和在位者，整体上仍然最功能丰富，但其他应用正在快速追平，某些具体场景甚至超过它。

例如，ChatGPT 现在有搜索，但 Perplexity 做搜索更久，搜索体验和模型都很好。想原型化简单 Web app 或生成图，Claude Artifacts 是 ChatGPT 没有的功能。想用语音和模型聊天，ChatGPT Advanced Voice 很不错；如果 ChatGPT 太谨慎，想要更娱乐化，可以试 Grok。不同应用都有强弱项，ChatGPT 仍是很好的默认选择，但不是唯一选择。

要跟踪这些应用和功能，可以按几条线索思考。

第一，你在和一个压缩包说话。要知道自己的价格层级和实际模型。大模型有更多世界知识、更能回答复杂问题、写作更好、更有创造性；小模型知识少、创意弱、更容易犯错和幻觉。

第二，思考模型是当前研究前沿之一，通常通过强化学习训练，能在数学、代码、推理问题上提高准确率。简单任务先用非思考模型；如果解决不了，再切换 reasoning/thinking 模式。

第三，工具能力正在快速增加。新鲜信息或不在压缩包里的知识，要用搜索。要画图、跑分析、计算，使用 Python interpreter 或 Advanced Data Analysis。要原型化小网页或生成图示，可以用 Artifacts。专业编程应使用 Cursor/Composer 这类能访问代码库的工具。

第四，多模态层正在成熟。输入和输出不再只是文本，还包括音频、图片和视频。有些模态是模型原生处理的，例如 Omni/multimodal model 直接处理音频或图像 token；有些是外挂模型通过文本和主模型沟通，例如 DALL·E 3 由主模型生成 caption 后交给图像模型。这个区别也值得注意。

第五，生活质量功能包括文件上传、记忆、自定义指令、自定义 GPT 等。不同功能可能只在网页端有，或者只在手机端有；不同平台的 app 和 browser 版本能力也可能不一致。整个生态快速变化且略显混乱，但这些就是使用时要寻找、比较、实验的能力。

### slide 18

最后一页给出一张使用决策表，把整节课变成实际操作。

- 如果问题是常见、稳定、低风险知识：可以直接问强模型，但重要时核查。
- 如果问题是近期、变化快、小众事实：打开搜索，要求引用，并查看来源。
- 如果问题需要多来源综合：用 Deep Research，把报告当第一稿和文献入口。
- 如果问题围绕具体材料：上传文件或粘贴原文，让模型基于上下文回答。
- 如果问题需要精确计算、图表、数据处理：让模型使用代码解释器，并审查代码和变量。
- 如果问题是编程项目：用 Cursor/Composer 这类有代码库上下文的工具，而不是只在网页里复制粘贴。
- 如果问题涉及语言学习、重复格式、个人偏好：用 custom instructions、memory、custom GPT 把长期设置固化。
- 如果输入输出更适合说、看、听：尝试语音、图片、视频和 NotebookLM 播客。

核心结论是：LLM 不是一个按钮，而是一套工具箱。会用 LLM 的人，不是把所有问题都丢给聊天框，而是知道什么时候该换模型、开搜索、上传材料、跑代码、用思考模式、换应用，最后再由自己检查结果并负责。
