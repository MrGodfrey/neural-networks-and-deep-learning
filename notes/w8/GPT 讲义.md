#  ChatGPT：从预训练到强化学习的讲义概览



## 1. 问题起点：ChatGPT 文本框背后是什么

大家都用过 ChatGPT、豆包、DeepSeek、元宝这类对话型人工智能。表面上看，它像一个魔镜：你问什么，它都能回答；如果拿它来写作业、写代码、做总结，它又像一盏阿拉丁神灯：你许一个愿望，然后等它把任务变出来。这个体验很容易让人觉得背后有一个魔法盒子，但它的底层仍然是这个学期反复学习的神经网络，只是结构更特殊、规模更大、训练流程更复杂。

我们在 ChatGPT 里看到的是一个文本框：输入任意内容，按下回车，系统返回一串文字。真正需要理解的问题是：这些文字从哪里来？模型到底在做什么？我们是在和什么东西对话？它为什么有些地方看起来很聪明，有些地方又会犯非常低级的错误？

构建一个类似 ChatGPT 的系统，大体可以分成三个训练阶段。第一阶段是预训练（pre-training），目标是从海量互联网文本中学习语言和世界知识，得到基础模型（base model）。第二阶段是后训练（post-training）中的监督微调（supervised fine-tuning, SFT），目标是把基础模型变成能和人对话的助手。第三阶段是强化学习（reinforcement learning, RL），目标是让模型通过练习和试错发展出更强的问题求解策略。

贯穿这三个阶段的核心机制非常简单：文本会先被切成 token，模型不断学习预测“下一个 token”。但这个简单目标在海量数据、巨大模型和复杂训练流程下，会涌现出非常强的语言、知识和推理能力。

这个机制可以理解成“文字接龙”。模型吐出一段文字后，系统把这段文字再接回输入，继续让模型预测下一个最可能出现的 token；再吐出一个，再接回去。整段回答不是一次性从模型里完整拿出来的，而是一个 token 一个 token 接出来的。把一个小模型下载到本地后，也可以把这个过程拆开观察：给模型一个前缀，看它下一步的概率分布，手动或自动选择 token，再把 token 拼回上下文。

三个训练阶段也可以用更口语的类比串起来。预训练让模型像牙牙学语的小孩一样阅读海量人类文本，学到语言范式和世界知识；结束后得到的 base model 更像一只会接话的鹦鹉，它能流畅续写，但还不是助手。SFT 是给它看“人类和合格助手应该怎样对话”的例题，让它从鹦鹉学舌转向助手行为。RL/RLHF 则让它自己做练习题或接受偏好反馈，学会更复杂、更有效的 token 生成策略。无论阶段怎么变，底层仍然是在改变“下一个 token 应该是什么”的概率。

### slide 1

先把问题压到最小单位：文本框里看似自然的一段回答，本质上是 token 序列生成。

- 用户看到的是“输入问题、得到回答”，但系统内部先把文本切成 token，再把 token 序列送进神经网络。
- 神经网络并不是一次性写完整段话，而是在每个位置预测“下一个 token”可能是什么。
- 预测结果是一个概率分布，系统从中选出一个 token，追加到已有上下文后，再重复同样过程。
- 因此，assistant 行为不是凭空出现的智能实体，而是由 tokenization、Transformer、采样策略、后训练规范共同塑造出来的生成行为。

后面所有章节都可以回到这条链路上理解：文本进入系统，变成 token；token 进入模型，变成概率；概率经过采样，变成新的 token；许多 token 连起来，才成为用户看到的回答。

### slide 2

整节内容的路线图是三个训练阶段。三个阶段可以理解成同一个模型在三种不同材料和目标下被塑造。

- 预训练像“读材料”：模型从海量文本中学习语言结构、事实知识、写作风格和常见推理模式，得到 base model。
- SFT 像“看例题”：模型看到大量 user/assistant 对话样例，学习什么叫回答问题、解释概念、拒绝不合适请求。
- RL/RLHF 像“做练习”：模型自己尝试不同回答或推理路径，成功的路径被强化，更符合偏好或更容易得到正确答案的行为会留下来。
- 三个阶段的数据不同、评价信号不同，但底层仍然都在改变模型生成 token 序列的概率。

由此可以得到一个总判断：ChatGPT 不是只靠预训练得到的。预训练让它会续写互联网文本，SFT 让它像助手一样说话，RL/RLHF 进一步调整它的求解策略和回答偏好。

## 2. 预训练数据：从互联网到高质量文本

预训练的第一步，是下载并处理互联网文本。一个可以参考的公开例子是 Hugging Face 的 FineWeb 数据集。OpenAI、Anthropic、Google 等公司内部也会有类似的数据集，只是来源、过滤策略和规模不同。

目标不是把整个互联网原封不动塞进训练集，而是获得大量、高质量、多样化的文档。多样性决定模型能覆盖多少知识领域，质量决定模型学到的模式是否可靠，数量则决定模型是否有足够多样本去学习语言和世界结构。

Common Crawl 的原始量级很直观：自动抓到的网页数据大约可以达到 10PB，也就是一万多个 TB。听起来极大，但如果按 2TB 硬盘估算，也就是几千块硬盘，一辆卡车就能装下。这个类比把“互联网很大”拉回工程尺度：原始数据确实庞大，但真正难的不是“有没有足够多字节”，而是哪些字节值得让模型学习。

许多数据构建流程从 Common Crawl 开始。Common Crawl 从 2007 年左右开始抓取互联网，到 2024 年已经索引了数十亿网页。它通过爬虫从种子网页出发，沿链接不断扩展，积累大量网页原始数据。但这些数据非常粗糙，不能直接训练模型。

原始网页首先要做 URL 过滤（URL filtering）。系统会去掉恶意软件网站、垃圾站、营销站、种族主义网站、成人内容网站等来源。然后做文本抽取（text extraction）：爬虫保存的是 HTML，其中有 CSS、脚本、导航栏、菜单、页脚等大量非正文内容，训练模型需要的是正文文本。之后还要做语言过滤（language filtering），例如 FineWeb 会用语言分类器判断网页语言，只保留英文比例超过一定阈值的网页，示例中提到的是英文超过 65%。这种阈值本身就是设计选择；如果训练集中过滤掉很多西班牙语，模型未来的西班牙语能力就会较弱。

URL 过滤也关联到模型安全问题。早期对齐还不够强的模型，有时会被用户用“我是网络安全研究者，要找危险网站来攻克它们、为人类造福”这类话术说服，去配合不该配合的请求。这个例子不需要展开提示词攻击细节，但它说明：数据过滤、后训练安全规范、推理时拒答策略是连在一起的，模型不是天然知道什么该做、什么不该做。

文本抽取的必要性也很直观。即使是一个正常网页，人眼觉得有价值的是正文，但爬虫拿到的往往是 HTML、CSS、脚本、导航栏、按钮、页脚和各种结构描述。网页源码中的大量内容并不是训练所需的语言材料。预训练数据工程首先要做的，就是把真正的正文从这些噪声里抽出来。

后续还会做质量过滤、去重（deduplication）和个人可识别信息（Personally Identifiable Information, PII）移除。PII 包括地址、社会安全号码等敏感信息。最终得到的数据看起来像大量网页正文：新闻、百科、技术文档、医学文章、论坛内容等。FineWeb 最终约 44TB，对应约 15 万亿个 token。这个数字相对整个互联网并不夸张，因为文本被强力筛选过，而且文本本身比图片、视频小得多。

一个很小的样本文档也能模拟真实流水线的几个动作：去掉全大写的垃圾段落、去掉重复句子、去掉太短的片段、替换可能的隐私信息。真实生产系统会复杂得多，会用分类器、规则、去重索引和人工评估，但小样本已经足够说明一件事：训练集不是“互联网本身”，而是经过很多工程选择后留下来的文本分布。

可以把这些文本想象成一张巨大的互联网文本织物。里面有语言结构、事实知识、写作风格、推理样式、网页格式和各种领域模式。预训练要做的，就是让神经网络学习这张文本织物如何延展。

### slide 3

互联网文本可以拆成一条工程管道。需要注意的是，模型并不是直接吞下整个互联网，而是训练在筛选后的文本分布上。

- Common Crawl 提供的是粗糙网页抓取结果，里面有广告、导航栏、脚本、重复页面、垃圾站和敏感信息。
- URL 过滤决定哪些网站或来源先被排除；这一步会影响模型接触到哪些主题和价值取向。
- 正文抽取把 HTML 中真正有语言价值的正文拿出来，去掉菜单、页脚、代码和样式噪声。
- 语言过滤、质量过滤、去重和 PII 移除继续压缩数据，使训练集更干净、更有代表性，也更安全。
- FineWeb 的 44TB、15 万亿 token、英文比例阈值等数字不是要背诵，而是用来感受预训练数据的量级和筛选强度。

关键结论是：训练数据本身就是设计产物。过滤掉什么、保留什么、如何定义“高质量”，都会进入模型未来的能力边界和偏差中。

## 3. Tokenization：模型不是直接看字符

神经网络不能直接处理“人类意义上的文本”，它需要一个有限符号集合上的一维序列。因此，原始文本必须先被转换成 token 序列，这个过程叫分词（tokenization）。

这和循环神经网络中遇到的是同一个问题：机器到底怎么处理文字？最朴素的办法，是把字符转换成二进制数字再拼起来。这样做可以工作，但序列会非常长，而且很多高层结构需要模型自己从很底层的 bit 里重新学出来。tokenization 的目标不是理解文本含义，而是先给模型一个可计算、长度相对可控的符号序列。

最底层看，文本可以用 UTF-8 编码成 0 和 1 的 bit 序列。但如果只用 0 和 1 两种符号，序列会非常长，而序列长度对模型来说是昂贵资源。可以把连续 8 个 bit 合成一个字节（byte），这样符号集合扩大到 256 个，序列长度缩短为原来的八分之一。这里的 0 到 255 不应理解为数值大小，而应理解为符号 ID。

生产级模型还会进一步压缩序列。常用方法是字节对编码（Byte Pair Encoding, BPE）。BPE 会寻找常见的相邻符号对，把它们合并成新符号。例如如果 116 后面跟 32 的组合经常出现，就可以创造一个新 token ID 表示这一对。不断重复合并，序列变短，词表变大。GPT-4 使用的词表大约有 100,277 个 token。

用 Tiktokenizer 这类工具可以直观看到 tokenization。选择 `cl100k_base` 后输入 `hello world`，它可能被分成 `hello` 和 ` world` 两个 token。改变大小写、空格数量或拼写，分词结果会变化。`Hello world`、`hello world`、`hello  world` 都可能对应不同 token 序列。

不同模型的 tokenizer 会有明显差别。比如 GPT-2 对英文 `hello world` 往往能按常见片段切得比较自然，但处理中文时，常常会出现一个汉字被拆到多个 token 里的情况，也就是说“模型看到的中文”和人看到的中文并不一致。千问一类对中文更友好的模型，中文切分通常会好很多。这不是小细节：tokenizer 的设计会影响模型的序列长度、训练效率和不同语言上的能力。

这个事实非常重要：模型的世界是 token 世界，不是字符世界。它不一定直接看到单个字母，这会解释后面许多看似奇怪的失败，例如数不清 `strawberry` 中有几个 `r`，或者处理拼写任务不稳定。

### slide 4

核心转折是：模型看到的不是人眼中的句子、单词或字符，而是一串 token ID。

- 文本先经过 UTF-8 等编码变成字节，字节可以看成 0 到 255 的符号 ID。
- 直接用字节训练会让序列太长，所以 BPE 会把常见相邻符号合并成更大的 token。
- `hello world` 可能只对应两个 token，其中空格也可能和后面的词合在一起；大小写、空格数量、标点都会改变 tokenization 结果。
- token ID 只是符号，不应该把它们理解成普通数字大小。模型学习的是这些符号在上下文中的关系。
- `strawberry` 的例子提前提示一个后果：人类能直接看到 10 个字母，模型却可能先看到几个合并后的 token。

所以，“模型会语言”不等于“模型天然会逐字符操作”。后面讨论计数、拼写、小数比较等错误时，都要回到这里：模型的基本观察单位已经和人类不同。

## 4. 预训练目标：预测下一个 token

有了 token 序列后，就可以训练神经网络。训练目标是：给定前面的 token，预测下一个 token。

训练时会从数据集中随机取一段 token 窗口（window）。窗口长度可以从 0 到某个最大值，例如 4,000、8,000、16,000 个 token，现代模型可以更长。窗口越长，计算越贵，所以必须设置最大上下文长度（context length）。

假设当前上下文只有 4 个 token，模型要预测第 5 个 token。模型输出一个长度等于词表大小的概率向量。如果词表有 100,277 个 token，模型就输出 100,277 个概率，表示每个 token 成为下一个 token 的可能性。

刚开始参数随机，预测也近似随机。但训练数据中真实的下一个 token 是已知的。训练算法会调整参数，让正确 token 的概率稍微升高，其他 token 的概率相对降低。这个更新会在大量 token 位置上并行发生。实际训练不是一个窗口一个窗口慢慢做，而是采样大量窗口组成 batch，在 GPU 上并行计算。

模型参数也叫权重（weights）。可以把它们想象成调音台上的旋钮。训练就是寻找一组旋钮设置，使模型对训练集中各种上下文给出的下一个 token 概率尽量合理。

为了把问题压到最小，可以考虑一个非常迷你的字符级模型。最简单的非平凡版本甚至可以只有一个参数矩阵：如果字符集大小是 `V`，矩阵第 `i` 行就表示“看到编号为 `i` 的字符后，下一个字符落在 `V` 个候选上的概率分布”。训练目标仍然是交叉熵损失：真实下一个字符概率越低，loss 越大；梯度下降会调整矩阵，让训练语料中真实后继字符的概率升高。

这个小模型训练前采样，通常是一长串近似乱码；训练后再采样，可能已经出现 `the`、`he`、`one` 这类局部像英文的片段，但整体仍然胡言乱语。它和 ChatGPT 当然差很多，但抽象目标是一样的：根据已有 token 预测下一个 token，只是大模型用 Transformer、巨大参数量和海量数据把这个目标推到了极高规模。

### slide 5

预训练目标可以压成一个最小训练样本：给定前面的 token，预测下一个 token。

- 左侧窗口表示上下文，模型只能根据窗口中已有 token 来判断下一个位置应该出现什么。
- 右侧柱状图表示词表上所有 token 的概率分布；如果词表有十万多个 token，模型每一步就要给十万多个候选分配概率。
- 绿色柱子代表训练数据里真实出现的下一个 token。训练的方向就是把这个 token 的概率提高。
- loss 可以直观理解成一种惩罚：正确 token 的概率越低，惩罚越大；概率越高，惩罚越小。
- 实际训练会在很多窗口、很多 token 位置上并行做这件事，再用梯度下降微调大量权重。

这里最重要的不是公式，而是因果关系：模型不是被显式灌输“事实列表”，而是在无数次下一个 token 预测中，被迫学习语言结构、世界知识和常见推理模式。

## 5. Transformer：一个巨大的可训练数学函数

现代大语言模型通常使用 Transformer 架构（Transformer architecture）。Transformer 本质上是一个由大量参数控制的数学函数：输入 token 序列，输出下一个 token 的概率分布。

输入 token 首先会被映射成向量，这一步叫嵌入（embedding）。之后信息流过层归一化（layer normalization）、矩阵乘法（matrix multiplication）、注意力模块（attention block）、softmax、多层感知机（multi-layer perceptron, MLP）等结构。每一层都只是相对简单的数学操作，但堆叠起来后表达能力非常强。

这些中间值有时可以类比为“合成神经元”的激活，但不要把它们过度等同于生物神经元。生物神经元是复杂动态系统，有记忆和时间行为；Transformer 前向计算则是无状态（stateless）的固定数学表达式。模型的“记忆”主要在参数中，不是在某个运行时自我里。

神经网络架构研究关心的，是如何设计既表达能力强、又容易优化、还能高效并行的数学表达式。最终目标仍然是让模型的预测符合训练数据中的统计规律。

此处暂时不需要展开 Transformer 的完整公式，关键是两个直觉。第一，它相对循环神经网络的重要改进，是可以让不同位置通过 attention 直接计算相关性，而不是只能按时间步一步传递。第二，它的主要计算是大规模矩阵乘法，因此天然适合 GPU 并行训练。大公司买 GPU，本质上是在买更快做这些矩阵乘法、更快处理 token 的能力。

### slide 6

Transformer 的全部数学细节此处不必展开，先看前向计算的骨架。

- token ID 先进入 embedding，被转换成向量。向量比 ID 更适合表达语义、位置和上下文关系。
- attention 让每个位置从上下文中读取相关信息。一个 token 后续如何被理解，取决于它能和哪些前文 token 建立联系。
- MLP 对每个位置的向量继续做非线性变换，形成更复杂的特征。
- 多层结构反复堆叠后，最后输出 logits，再通过 softmax 变成下一个 token 的概率分布。
- 图下方的 layer norm、matrix multiply、softmax、activation 都是普通数学操作，只是规模非常大、参数非常多。

需要避免一个误解：Transformer 前向计算不是一个持续存在的“自我”在思考，而是一组固定权重控制的数学函数。模型的长期知识主要存在参数里，当前可读取的信息主要存在上下文里。

## 6. 推理：训练完后只是继续补全 token

训练结束后，模型参数固定。用户使用 ChatGPT 时，通常不会继续训练模型，而是在做推理（inference）。

推理过程也很简单：给模型一段前缀 token，模型输出下一个 token 的概率分布；系统根据这个分布采样一个 token，把它追加到序列末尾；再把新序列送回模型，继续采样。这样一个 token 一个 token 地生成，就得到用户看到的文本。

因为每一步都是采样，所以系统是随机的（stochastic）。同一个前缀多次运行可能得到不同回答。有时模型会复现训练数据中的小片段，有时会生成训练集中没有逐字出现过的新组合。它生成的不是简单复制，而是训练数据统计模式的重组。

观察一个小的 instruct 模型解释 tokenization 时，可以不急着看完整回答，而是先看第一个位置的概率分布：概率最高的 token 可能是大写 `T` 开头，也可能有一些看起来奇怪但能接上的候选。模型选出一个 token 后，把它拼回输入，再重新计算下一步概率。这个循环一旦被拆开，就能看到“回答”其实是很多次很小的选择叠出来的。

温度（temperature）控制采样时容纳多少随机性。若每次都选概率最高的 token，同一个模型、同一个输入就会趋向于给出相同结果，输出稳定但缺乏变化。调高温度，相当于让低概率候选也有更多机会被采到，文本会更自由、更发散，也更容易跑偏。同一 prompt 在不同温度下多次生成，往往就能看到“稳”和“自由奔放”的差别。

### slide 7

训练后的使用过程是一个循环。训练结束后，权重固定下来，用户请求通常不会继续修改模型参数。

- 用户输入和对话历史先组成前缀 token。
- 模型根据前缀输出下一个 token 的概率分布。
- 系统按照温度、top-p 等采样设置，从分布中选出一个 token。
- 新 token 被追加到上下文末尾，模型再基于更长的上下文预测下一个 token。
- 循环停止条件可能是生成了结束标记、达到长度限制，或者系统决定中断。

训练和推理可以对照理解：训练时，真实下一个 token 已知，系统用它来更新权重；推理时，权重不再更新，只反复执行“预测、采样、追加”。同一个 prompt 多次得到不同回答，也正是因为采样过程带有随机性。

## 7. GPT-2：现代大模型栈的早期样本

GPT-2 是理解这一流程的好例子。GPT 是生成式预训练 Transformer（Generatively Pre-trained Transformer）的缩写。GPT-2 是 OpenAI 在 2019 年发布的第二代 GPT 模型。它之所以重要，是因为很多今天仍然使用的现代大模型组件，在 GPT-2 中已经组合在一起了。

GPT-2 大约有 15 亿到 16 亿参数，最大上下文长度是 1,024 个 token，训练数据约 1,000 亿 token。现代模型在这些维度上大得多：参数可能达到数千亿，上下文长度可能达到几十万甚至上百万 token，训练 token 数可以达到十几万亿。

训练 GPT-2 时，研究者会看训练日志中的损失（loss）。loss 越低，表示模型越擅长预测下一个 token。每一行日志通常代表一次参数更新；示例中一次更新可能处理 100 万 token，每步大约 7 秒，总共计划训练 32,000 步，也就是约 330 亿 token。

训练初期，模型生成文本近似乱码。训练一小段时间后，文本出现局部英语结构，但整体仍不连贯。随着 loss 下降，模型逐渐生成更像自然语言的内容。研究者训练模型时，经常就是确认 loss 稳定下降，训练没有崩，然后等待计算完成。

2019 年训练 GPT-2 估计要花数万美元。后来成本下降明显，原因包括数据过滤更好、GPU 更快、训练软件更能压榨硬件性能。作者提到自己在 `llm.c` 项目中复现 GPT-2，约一天和 600 美元可以完成，进一步优化甚至可能接近 100 美元。

## 8. 计算资源：GPU 和数据中心在做什么

训练 GPT-2 或更大的模型不能靠普通笔记本完成。示例中使用的是云端一台 8×H100 节点，也就是一台服务器中有 8 张 NVIDIA H100 GPU。作者提到可以从 Lambda 等云服务商租用，示例价格是每张 H100 每小时约 3 美元。

GPU 适合训练神经网络，因为神经网络中大量矩阵乘法可以并行。一个节点可以有多张 GPU，多个节点组成系统，许多系统组成数据中心。大公司争夺 GPU，本质上是争夺更快处理 token、更快训练模型、更快迭代实验的能力。

新闻中提到的 10 万张 GPU 数据中心，看起来宏大，但核心工作仍然是：在巨大数据集上预测下一个 token，并不断更新参数。更多 GPU 只是让这个过程更快、更大、更可扩展。

### slide 8

GPT-2 是现代大模型栈的早期样本，也能说明算力为什么重要。

- GPT-2 的 15 亿左右参数、1024 token 上下文、约 1000 亿 token 训练数据，在今天看不算最大，但已经包含了“生成式预训练 Transformer”的基本形态。
- 训练日志中的 loss 下降，是研究者判断模型是否正在学会预测下一个 token 的核心信号。
- 早期生成近似乱码，随后出现局部英语结构，再逐渐变得连贯，这个过程对应模型对文本分布的逐步拟合。
- H100、8 卡节点、GPU 集群、数据中心这些硬件，服务的是同一个目标：更快处理更多 token，更快完成更多参数更新。
- 参数规模、上下文长度、训练 token 数、硬件吞吐量共同决定训练成本和模型上限。

不要被数据中心的规模遮住抽象本质。无论是 GPT-2 还是更大的模型，核心训练动作仍然是：在海量文本窗口上预测下一个 token，并让 loss 稳定下降。

## 9. 基础模型：互联网文档模拟器

预训练结束后得到的是基础模型（base model）。基础模型不是助手，而是 token 层面的互联网文本模拟器。它会继续补全输入前缀，使生成文本统计上类似训练过的互联网文档。

也可以把 base model 说成一只很厉害的鹦鹉：你给它一句话，它能迅速接下去，而且接得像人类文本；但鹦鹉不会自动成为助手。用户问“2 加 2 等于几”，它也许会接出答案，也许会继续补出测验、网页、论坛对话或一段毫无意义但流畅的文字。关键不在于它完全没有知识，而在于它默认并不知道自己应该站在“助手回答用户”的角色里。

发布模型通常需要两样东西。第一是代码，描述神经网络前向传播（forward pass）的具体结构。第二是参数，也就是训练后得到的那一长串数字。代码相对标准，真正的价值在参数中。

GPT-2 发布过基础模型。更现代的例子是 Meta 的 Llama 3.1 405B base，它有约 4050 亿参数，在约 15 万亿 token 上训练。Meta 同时发布基础模型和指令模型（instruct model）。基础模型只是续写器；指令模型才更像助手。

如果把 `What is 2 + 2?` 输入基础模型，它不一定回答“4”。它可能回答，也可能转向其他文本，因为它只是在继续互联网文档序列。用 Hyperbolic 这类平台可以体验 Llama 3.1 405B base，观察这种纯自动补全行为。

基础模型仍然很有用，因为为了预测下一个 token，它必须把大量世界知识压缩进参数。可以把 4050 亿参数看作互联网的有损压缩（lossy compression）：不是精确数据库，而是模糊、概率性的记忆。常见信息更容易记住，罕见信息更容易出错。

这种模糊记忆会产生几种现象。第一，模型可能背诵训练数据，例如给它维基百科“斑马”词条开头，它可能继续生成大段原文，这叫复述（regurgitation）。第二，如果给它训练截止日期之后的信息，例如 2024 年美国总统选举，它会根据旧知识猜测，生成一个看似合理但错误的平行世界。第三，基础模型也能通过少样本提示（few-shot prompt）完成任务，例如给出多组英文到韩文翻译，最后写 `teacher:`，它可能根据上下文学习模式并补出韩文翻译。这叫上下文学习（in-context learning）。

甚至可以只靠提示把基础模型临时伪装成助手：写一段“下面是人类和乐于助人的 AI 助手之间的对话”，给几轮 `Human:` / `Assistant:` 示例，再输入真正问题。基础模型会因为上下文像对话而继续写助手回答。但它仍然只是续写，可能回答完后继续幻觉下一轮人类问题。

### slide 9

base model 和 instruct model 需要分清楚。二者可能共享相似架构，但行为目标不同。

- base model 的默认任务是继续补全文档。给它一个前缀，它会生成统计上像互联网文本后续内容的 token。
- `What is 2 + 2?` 在 base model 看来不一定是“用户正在提问”，也可能只是网页、论坛、测验、教材中的一段文本。
- instruct model 经过后训练，学会把类似输入解释成用户请求，并生成助手式回答。
- base model 的参数里仍然压缩了大量知识，所以它可以通过 few-shot prompt 临时完成翻译、问答或对话补全。
- 但这种能力是上下文诱导出来的续写行为，不等同于已经具备稳定助手人格。

关键判断是：基础模型很强，但它首先是互联网文档模拟器。ChatGPT 式体验还需要后训练把“继续文档”的能力转成“按用户意图回答”的行为。

## 10. 后训练：把基础模型变成助手

要得到真正的 ChatGPT 式助手，需要后训练（post-training）。后训练计算量通常远小于预训练：预训练可能需要数千台机器训练数月，后训练可能只需要几小时。但它决定模型如何与人互动，所以非常关键。

后训练首先把互联网文档数据集换成对话数据集。对话可以是多轮的：用户问问题，助手回答；用户追问，助手继续解释。训练数据还会包含助手的语气、礼貌程度、拒答行为等。例如用户请求不该帮助的事情，理想助手应该拒绝（refusal）。

神经网络不能像普通程序那样显式写规则。我们主要通过示例“编程”它：给它大量人类与助手的对话，让它模仿这些对话中助手的行为。这就是监督微调（SFT）。算法上它和预训练仍然相似，都是预测下一个 token；区别只是数据从互联网文档换成对话。

对话也必须被编码成 token 序列。一个可能的协议是用特殊 token 表示消息边界和角色，例如 `<|im_start|> user <|im_sep|> What is 2 + 2? <|im_end|>`。这些特殊 token 不是普通文本，而是后训练阶段加入的结构标记。不同公司和模型格式不同，但核心相同：结构化对话最终仍是一维 token 序列。

推理时，服务器会把已有对话历史编码成 token，再在末尾放入“assistant 开始回答”的标记。模型从这里开始采样，生成助手回复。

同一个 instruct 模型，如果用官方 chat template，把 system、user、assistant 边界和特殊 token 都放对，回答通常稳定得多；如果只把一句话当普通续写前缀塞进去，模型可能表现得像被临时诱导的续写器。这个差别说明，后训练后的模型不是单靠一句自然语言 prompt 运转，产品层的对话协议也在强烈塑造行为。

多轮对话中的“记忆”也要在这里澄清。模型本身每次推理后参数不会改变，它之所以记得刚才聊了什么，通常只是因为服务器把前几轮 user/assistant 消息全部塞回上下文。带上历史时，问“刚才我们在干什么”，模型能回答；不带历史时，它只能根据当前一句话猜，甚至编造一个场景。系统提示词也是同一机制：当前时间、地点、模型身份、回答规范等信息，如果不在系统消息或上下文里，模型并不会凭空知道。

## 11. SFT 数据：人类标注、合成数据和助手人格

OpenAI 的 InstructGPT 论文较早系统介绍了这种后训练流程。OpenAI 通过 Upwork、Scale AI 等渠道雇佣人类标注员，让他们写 prompt 和理想助手回答。标注员会提出各种任务，例如职业建议、科幻小说推荐、翻译等，然后根据公司提供的标注说明写理想回答。

标注说明通常要求回答有帮助（helpful）、真实（truthful）、无害（harmless）。实际内部文档可能长达数百页，标注员要学习这些规则。模型在这些对话上训练后，就会统计性地模仿这种“乐于助人、真实、无害”的助手人格。

OpenAI 没有公开 InstructGPT 数据集，但 OpenAssistant 等开源项目展示了类似数据构建方式。例如用户问“请解释经济学中垄断的意义，并举例说明”，助手写出回答；用户再说“请把它解释给一只狗听”，助手改用更简单的表达。

现代 SFT 数据不再完全由人类从零写。现有 LLM 会大量参与数据生成：先由模型生成草稿，再由人类编辑、筛选、混合。UltraChat 等数据集包含数百万对话，其中很多是合成数据（synthetic data），但通常仍有人类监督。

因此，和 ChatGPT 对话时，一个有用心理模型是：它在统计上模拟一位受过公司标注说明训练的人类标注员。这个标注员可能在代码、数学等领域比较专业，但本质仍是被模型模拟出来的标注行为。问“推荐巴黎五个地标”时，模型不是实时研究世界，而是在结合预训练知识和后训练回答风格，生成一个类似标注员会写出的回答。

这里会出现一个自然问题：如果人类不可能把所有问题都示范一遍，模型是不是就永远学不会人类没有示范过的解法？这个问题把 SFT 引向 RL。SFT 的优势是教会模型“合格助手应该长什么样”，但它仍然主要是在模仿例题；对于代码、数学这类可以自动验证的任务，更强的办法是让模型自己尝试、自己练习。

### slide 10

SFT 可以理解成“用示例编程助手人格”。这里的“编程”不是写 if-else 规则，而是用大量对话样例改变模型的生成概率。

- system、user、assistant 这些角色最终都会被编码成特殊 token 和普通文本 token 的一维序列。
- 模型在 SFT 中继续做下一个 token 预测，但训练材料从互联网文档换成了理想对话。
- 标注员或合成数据给出示范：怎样回答职业建议、翻译、解释概念，怎样在危险请求中拒绝。
- Helpful、Truthful、Harmless 可以看成标注规范的三个方向，但它们不是硬编码在模型里的三条规则。
- 模型学到的是“在这种上下文里，受过标注规范训练的助手通常会怎样继续写”。

因此，后训练的力量在于改变默认续写风格。base model 看到问题可能继续写网页文本；SFT 后的模型更可能进入 assistant 角色，用礼貌、结构化、符合规范的方式回答。

## 12. 幻觉：模型为什么会自信地编造

幻觉（hallucination）指模型编造事实、人物、来源或细节，并用自信语气说出来。它不是偶然小毛病，而是训练方式自然带来的问题。

训练集中有很多“谁是某某？”的问题，例如 Tom Cruise、某位参议员、成吉思汗。标注员知道答案或查资料后，会写出自信回答。测试时，如果用户问一个不存在或模型不知道的人名，例如 `Orson Kovats`，模型仍然会模仿“谁是 X”问题的回答格式，给出看似合理的人物介绍。

旧模型 Falcon 7B Instruct 会明显表现出这一点。问它 `Who is Orson Kovats?`，一次可能说这是美国科幻作家，下一次说是电视剧角色，再下一次说是棒球运动员。每次不同，说明它并不知道，只是在概率分布中采样。

现代模型的一个缓解方法，是训练它在不知道时说“不知道”。Meta 在 Llama 3 中把这叫事实性（factuality）问题。方法是从训练文档中抽取段落，让 LLM 生成事实问答，再用目标模型多次回答这些问题。比如关于 Dominik Hasek 的段落，可以问“他为哪支球队效力？”“他赢过几次 Stanley Cup？”如果模型多次答对，说明它知道；如果答错或不稳定，说明它不知道。对于不知道的问题，训练集中加入新对话，让理想助手回答“抱歉，我不知道”。

可以想象模型内部可能已经有某些“不确定”的激活模式，但原本没有和“我不知道”这句话连接起来。通过这些训练样例，模型学会把内部不确定性表达出来。

虚构名字很容易触发幻觉。不给任何背景时，模型可能流畅地编出这个人是谁、做过什么、为什么重要；多问几次，身份还可能每次都不同。再把“这个名字只是人为构造的虚拟名字”作为上下文材料给它，模型就能基于材料明确说明这是虚构名字。这个对比很重要：模型不是不能使用事实，而是参数里的模糊记忆和上下文里的明确材料可靠性不同。

### slide 11

`Orson Kovats` 的例子说明了幻觉为什么会自然发生。幻觉不是简单的“模型故意撒谎”，而是生成目标和训练数据共同造成的副作用。

- 训练集中有大量“Who is X?” 类型问答。多数情况下，理想回答是自信地介绍这个人。
- 当 X 换成不存在或模型不知道的名字时，模型仍然可能复用这种回答格式，生成一个看似完整的人物简介。
- 如果多次询问得到不同身份，例如作家、角色、运动员，就说明模型没有稳定事实记忆，只是在采样相似模式。
- 事实性训练会先找出模型答不稳或答错的问题，再加入“抱歉，我不知道”的理想回答。
- 这样做的目标，是把模型内部的不确定信号和外部的“不知道”表达连接起来。

使用时需要保持警觉：流畅、自信、结构完整，并不等于事实可靠。越是罕见人物、最新事件、精确来源，越应该要求检索、引用或独立验证。

## 13. 工具使用：把模糊记忆变成工作记忆

第二个缓解幻觉的方法是工具使用（tool use）。模型参数中的知识像模糊回忆：常见事实记得较牢，罕见事实记得不清。上下文窗口（context window）中的内容则像工作记忆（working memory），模型当前可以直接读取。

工具使用可以从两个问题理解。第一，训练好的模型知识按理说停在训练截止时刻，为什么现在的产品能回答最近发生的事？通常是因为接入了搜索或浏览工具。第二，模型靠文字接龙为什么能算很大的乘法？通常是因为它把表达式交给代码解释器或计算器，而不是自己在参数里心算。

如果人类不知道一个事实，会去搜索。模型也可以通过特殊 token 调用工具。例如模型生成 `<search_start>`，后面跟搜索查询，再生成 `<search_end>`。推理程序看到搜索结束标记后暂停采样，调用 Bing 或 Google，把搜索结果文本插入上下文窗口，然后让模型继续生成。此时模型可以直接引用这些新文本，而不是依赖模糊记忆。

模型如何学会工具？仍然靠训练数据。训练集中要展示什么时候搜索、如何写查询、搜索结果如何插入上下文、如何引用来源。只要示例足够，模型就能学会这个协议。

本地工具调用尤其需要安全边界。比如我们写一个只会计算数学表达式的工具，不能直接 `eval` 模型吐出的任意字符串，因为模型可能被用户“摁头”输出恶意代码。更安全的做法是先检查表达式只包含数字、括号和基本运算符，或者用受限解析器解析 AST，确认合规后才执行。工具调用协议也要明确：要求模型输出某段 JSON，里面写清工具名和参数；如果 JSON 格式不对，就把错误反馈给模型，让它重新生成；格式正确后再执行工具，把结果放回上下文，最后让模型基于工具结果回答用户。

大数乘法能把差别显示得很清楚。不给工具时，模型对两个从未在互联网出现过的大数相乘，大概率会编一个看似合理但错误的数字；允许它按协议调用计算工具后，结果马上变正确。现代 AI 产品已经不只是“会接词的神经网络”，而是“神经网络加上下文、工具、校验和产品协议”的系统。

这个区分对使用模型很重要。让模型总结《傲慢与偏见》第一章时，直接问它，它会凭记忆回答；把第一章原文粘贴进上下文，它会直接读取材料，摘要通常更可靠。实际使用中，重要材料应尽量放进上下文，事实问题应允许模型搜索，计算问题应允许模型调用代码。

### slide 12

工具使用可以放在“记忆”框架里理解。模型参数里的知识像模糊压缩，当前上下文和工具结果才是可直接读取的工作记忆。

- 事实题适合搜索。模型先生成查询，系统调用搜索工具，再把网页摘要或来源放回上下文。
- 精确计算、计数、字符串处理适合代码。模型写程序，让解释器给出确定结果。
- 材料题最好直接提供原文。让模型总结、改写、比较时，原文在上下文中比模糊记忆可靠得多。
- 工具调用本身也是一种协议，模型需要通过训练样例学会何时调用、如何组织查询、如何引用结果。
- 工具不会自动保证正确，仍然需要检查输入是否完整、查询是否合适、代码是否真的运行、来源是否可信。

使用上的原则很直接：重要事实不要只靠模型背，精确操作不要只靠模型心算，长材料不要只让模型凭印象总结。把材料和工具放进上下文，模型就从“凭记忆回答”转向“基于工作台处理”。

## 14. 模型的“自我知识”是被附加出来的

很多人会问模型：“你是什么模型？”“谁开发了你？”这类问题要谨慎理解。语言模型不是一个持续存在的人。它每次请求时读取上下文、计算 token、生成结果，然后这次计算结束。它没有跨对话持续存在的自我。

如果没有显式训练或系统提示，模型对“你是谁”的回答只是统计猜测。旧模型可能声称自己由 OpenAI 构建、基于 GPT-3，即使事实并非如此。这不一定说明它使用了 OpenAI 私有数据；更可能是互联网中大量助手身份文本都指向 ChatGPT 和 OpenAI，所以模型套用了这个标签。

开发者可以用两种方式固定身份回答。第一是在 SFT 数据中加入硬编码问答，例如 OLMo 数据里有约 240 条关于自身身份的对话，明确回答“我是 Allen Institute for AI 开发的开放语言模型”。第二是在对话前加入系统消息（system message），用用户看不到但模型能看到的 token 告诉它身份、知识截止日期和行为规则。

所以模型的自我知识不是人的自我意识，而是训练数据和系统消息塑造出来的设定。

一个有趣的例子是“把还没说出口的话塞到模型嘴里”。如果正常问千问模型“你是谁”，它可能回答自己是千问；但如果在上下文里强行写成“助手：我是林俊杰，因为……”，模型后续就可能顺着这个角色继续编造。这不是模型真的变成了某个人，而是上下文里的角色设定改变了后续 token 的概率。这个例子也能解释为什么 system prompt、chat template 和对话历史会如此重要。

### slide 13

“你是谁”这类问题不能按人类自我认知来理解。

- 模型每次请求都是读取当前上下文，运行一次又一次前向计算，生成 token，然后本次计算结束。
- 它没有一个跨请求连续存在的自我，也不会天然知道自己被部署在哪个产品里。
- 身份回答可能来自 SFT 数据中的固定问答，也可能来自系统消息中的隐藏设定。
- 如果这些设定缺失或冲突，模型可能根据互联网中常见的助手身份文本猜测，例如把自己说成 ChatGPT 或 OpenAI 模型。
- 这类回答更接近“当前上下文诱导出的角色设定”，不是模型对自身内部状态的可靠内省。

因此，问模型身份、开发者、知识截止日期时，要把答案看成产品层和训练层共同提供的说明。它可以有用，但不是意识证明，也不是自动可信的事实来源。

## 15. 模型需要 token 来思考

语言模型从左到右一个 token 一个 token 生成。每生成一个 token，只有一次有限规模的前向计算。即使现代模型有很多层，也不是无限计算机。因此不能要求模型在一个 token 中完成复杂推理。

苹果和橙子的例子很好说明这一点：Emily 买 3 个苹果和 2 个橙子，每个橙子 2 美元，总价 13 美元，问每个苹果多少钱。如果回答一开始就写“答案是 3 美元”，模型在生成 `3` 这个 token 的瞬间必须完成全部计算，后面解释只是事后辩护。更好的回答是先算橙子总价 4 美元，再算苹果总价 9 美元，再算每个苹果 3 美元。这样计算被分散到多个 token，中间结果进入上下文，模型更容易可靠求解。

这也是为什么 ChatGPT 常常写“设变量”“列方程”“逐步求解”。这些步骤不仅是给人看的，也是给模型自己用的。它需要把计算展开到 token 序列中。

如果强制模型“只用一个 token 回答”，简单题可能答对；但把数字变大，例如 23 个苹果、177 个橙子，它可能直接算错。放开 token，让它逐步推理，就更可能正确。对于精确计算，更可靠的方法是让模型使用代码解释器（code interpreter），写 Python 程序并运行，把算术交给工具。

如果让模型直接回答一道小学应用题，它可能因为一开始就急着吐出答案而算错；如果要求它“一步一步说出怎么想”，中间量会被写进上下文，后续 token 可以继续读取这些中间量，正确率就可能提高。需要注意的是，逐步推理不是万能药；研究者对思维链到底提升了多少能力仍有争论，但它至少说明了一个机制：模型需要把一部分计算展开成 token，才能在有限前向计算里做复杂事。

## 16. 计数、拼写和奇怪失败

模型不擅长计数，因为它看到的是 token，不是人眼中的字符。给它一长串点号问有多少个点，它可能答错；分词器可能把很多连续点号合成少数 token，模型必须从 token ID 中完成计数。如果要求“use code”，它只需把点号复制成 Python 字符串，再调用 `.count()`，结果会可靠得多。

拼写任务也类似。`ubiquitous` 可能被分成多个 token。人类能直接看到每个字母，但模型不一定能自然索引字符。让它“从第一个字符开始每隔三个字符取一个”容易失败；让它用 Python 处理字符串通常更可靠。

著名例子是 `strawberry` 里有几个 `r`。早期很多强模型会说两个，而正确答案是三个。这个任务同时要求字符访问和计数，正好击中 tokenization 和计数能力的弱点。

还有更奇怪的失败，例如模型有时会判断 `9.11` 大于 `9.9`。有研究发现，内部激活可能被《圣经》章节编号模式干扰：在章节语境中 9:11 确实在 9:9 之后。这类现象说明模型能力像瑞士奶酪：整体非常强，但有很多孔。它可以解奥赛题，也可能在简单计数、拼写、小数比较上犯错。

### slide 14

这里把两个看似不同的问题放在一起：模型为什么需要中间步骤，以及它为什么会在简单任务上犯错。

- 模型从左到右生成 token。让它第一个 token 就给出复杂题答案，相当于要求它在一次有限前向计算中完成全部推理。
- 分步骤写出橙子总价、苹果总价、每个苹果价格，中间结果会进入上下文，后续 token 可以继续读取这些结果。
- 所谓 chain-of-thought 或逐步推理，对模型来说不只是展示给人看的解释，也是把计算展开到 token 序列中的方法。
- 计数和拼写错误来自另一个层面：模型的输入单位是 token，不是稳定可索引的字符数组。
- `strawberry` 中有几个 `r`、一串点有几个、从单词中每隔三个字符取一个，都可能被 tokenization 干扰。
- `9.11` 和 `9.9` 这类小数比较错误，则说明模型会受到训练分布中其他模式牵引。

可靠策略是区分任务类型：需要推理时给模型足够 token 展开步骤；需要精确计算、计数和字符串操作时，让模型调用代码，把确定性工作交给工具。

## 17. 强化学习：让模型自己练习

预训练相当于读讲解材料，SFT 相当于看专家例题。强化学习（RL）对应做练习题：题目给出，最终答案可检查，但完整解法没有给出。模型需要自己尝试不同解法，发现哪些 token 序列能得到正确答案。

为什么不直接让人类写最佳解法？因为人类认知和模型认知不同。人类觉得自然的一步，对模型可能是过大的跳跃；人类觉得啰嗦的中间步骤，对模型可能正好有用；反过来，人类写的一些解释对模型可能只是浪费 token。我们不知道哪条 token 序列最适合模型。

RL 的基本流程是：给定一个 prompt，让模型采样许多候选解法。因为采样随机，同一题会有很多不同路径。系统检查哪些解法得到正确答案，哪些没有。正确路径被强化，未来类似问题中模型更可能生成这些路径。

可以想象一个题目采样 15 个解法，其中 4 个正确。绿色路径代表正确，红色路径代表错误。系统可以挑出正确且较好的路径训练模型。重要的是，这些成功解法来自模型自己，而不是人类标注员。SFT 把模型初始化到“大概会写解题过程”的区域，RL 则让它自己调优出更适合自身的策略。

这里要小心“微调”的说法。广义 fine-tuning 可以调整模型全部参数，也可以用 LoRA、adapter 等方法只调整少量新增或低秩参数；“微调比从头训练便宜很多”通常是对的，但不能把所有微调都说成必然固定绝大多数参数。相对于预训练几个月的量级，后训练或某些微调可能只需要几小时到几天，但这取决于模型大小、数据量和训练方式。

## 18. DeepSeek R1 和思考模型

DeepSeek R1 论文公开展示了 RL 微调大语言模型的效果。随着 RL 步数增加，模型在数学题上的准确率上升。更有趣的是回答长度变长，模型开始生成类似“等等，我需要重新检查”“换个角度再算一遍”的推理内容。

这些回溯、检查、换角度验证不是人类硬编码进去的，而是在追求正确答案的训练过程中涌现出来的。模型发现这些认知策略能提高正确率，于是学会使用它们。这类模型常叫推理模型或思考模型（reasoning model / thinking model）。

DeepSeek R1 解简单苹果题时，会先像内心独白一样尝试求解、检查、换方法验证，然后再给人类写出整洁答案。第一部分服务于正确性，第二部分服务于呈现。OpenAI 的 o1、o3 系列也属于类似思考模型。GPT-4o 这类普通模型更接近主要由 SFT 和 RLHF 塑造的助手，不会像思考模型那样长时间显式推理。

OpenAI 不展示完整思维链，只显示摘要，原因之一是蒸馏风险（distillation risk）：如果完整推理轨迹公开，别人可以用它训练模型，复制一部分推理能力。DeepSeek R1 则更直接展示推理过程。实际使用中，复杂数学、代码和多步推理适合尝试思考模型；简单事实问答通常不需要让模型长时间思考。

## 19. AlphaGo：RL 为什么可能超过模仿

强化学习的威力在 AlphaGo 中已经展示过。监督学习可以模仿人类专家棋局，但模仿人类会遇到上限，因为系统学的是人类分布。RL 优化的是“哪些动作最终会赢”，因此可以离开人类分布，发现人类不常用但有效的策略。

AlphaGo 对李世石的第 37 手就是经典例子。这一步在人类棋谱中极少见，许多人起初以为是错误，但后来证明非常精彩。它说明 RL 可以发现人类没有想到的策略。

大语言模型中的 RL 可能在开放问题求解中带来类似效果。模型也许会发现新的类比、新的推理策略，甚至某种更适合模型自己的中间语言。但这需要大量多样的可验证练习题，类似给模型写覆盖所有学科的练习册。

### slide 15

强化学习可以理解成“模型自己做练习”。给定同一个 prompt，模型可以随机采样出许多不同解法，其中一部分成功，一部分失败。

- SFT 提供了起点，让模型大概知道题目应该怎样展开、答案应该怎样呈现。
- RL 不要求人类写出最佳解法，而是让模型自己尝试多条 token 路径，再用奖励信号筛出成功路径。
- 正确路径被强化后，模型未来在相似问题上更容易生成检查、回溯、换角度验证等有用策略。
- DeepSeek R1 展示了这种现象：随着 RL 推进，模型回答变长，也更常出现自我检查和重新审视。
- AlphaGo 第 37 手说明 RL 可以离开人类示范分布，找到人类不常走但有效的策略。
- 前提是奖励要足够可靠。数学答案、代码测试、棋局胜负这类可验证信号，才能支撑更长时间的 RL。

核心区别是“模仿”与“练习”：SFT 主要模仿示范，RL 让模型在可检查任务上优化自己的成功策略。

## 20. 可验证 RL 与 RLHF

数学题、代码题属于可验证领域（verifiable domains）：答案可以自动检查。数学题可以比较最终答案，代码题可以运行测试，也可以用 LLM judge 判断解法是否与答案一致。这类环境的奖励很难被欺骗，因此可以较长时间运行 RL。

但很多任务不可验证（unverifiable）：写笑话、写诗、总结、创意写作。比如“写一个关于鹈鹕的笑话”，模型可以生成很多候选，但很难用简单规则判断哪个最好。让人类全部评分不可扩展，因为 RL 可能需要 1,000 次更新、每次 1,000 个 prompt、每个 prompt 1,000 个候选，总计 10 亿次评估。

强化学习来自人类反馈（Reinforcement Learning from Human Feedback, RLHF）用奖励模型（reward model）解决这个问题。人类不直接给每个候选打分，而是排序。例如给五个鹈鹕笑话，让人类从好到坏排序。奖励模型接收 prompt 和候选回答，输出一个分数；训练目标是让它的排序接近人类排序。之后语言模型就可以对奖励模型做 RL。

RLHF 的好处是把 RL 扩展到不可验证任务，而且利用了“判别比生成容易”的事实。让人类从五首诗中选更好的，比让人类从零写最好的一首诗容易。

RLHF 的问题是奖励模型只是人类偏好的有损模拟。RL 非常擅长找到奖励模型漏洞，生成在人类看来荒谬、但奖励模型给高分的对抗样本（adversarial examples），例如无意义的 `the the the ...`。把这个坏例子加入训练集只能修补一个漏洞，仍有无数其他漏洞。所以 RLHF 不能无限训练，通常只作为有限微调。作者说“RLHF is not RL”，意思是它不像数学、代码、围棋那样有不可欺骗的奖励函数，不能靠无限扩展产生同样强的“魔法”。

课程作业评分也能类比这个问题：如果用一个模型给作业打分，提交者也可以训练另一个模型专门对抗这个评分模型，生成“评分器喜欢但人未必认可”的答案。这个例子说明 reward model 不是客观真理，只是一个可被优化、也可被攻击的判别器。越是缺乏明确评价标准的任务，越要警惕模型学会的是“讨好评价器”，而不是真正把事情做好。

### slide 16

可验证 RL 和 RLHF 都属于强化学习相关方法，但奖励信号的性质很不一样。

- 数学、代码、围棋这类任务有较硬的奖励：答案对不对、测试过不过、棋局赢不赢，可以相对明确地判断。
- 诗、笑话、总结、语气这些任务没有简单标准。人类更容易比较几个候选哪个更好，而不是从零写出唯一正确答案。
- RLHF 先让人类对候选回答排序，再训练 reward model 去预测这种偏好排序。
- 语言模型随后不是直接对人类做 RL，而是对 reward model 做有限优化。
- 问题在于 reward model 只是人类偏好的近似。RL 过度优化它时，模型可能找到奖励模型漏洞，生成在人看来很差、但分数很高的回答。
- 所以 RLHF 很有用，却不能像数学、代码、围棋那样无限扩展训练。

边界很清楚：RLHF 能让回答更符合人类偏好，尤其是不可验证任务；但它不是不可欺骗的真理函数，奖励模型本身也需要被怀疑和约束。

## 21. 三阶段总图景

大语言模型训练可以类比教育过程。预训练像读教材讲解部分，建立知识基础；SFT 像看专家写好的例题解法，学习如何作答；RL 像做练习题，通过试错发现自己的解题策略。

今天的大模型公司实际上在为 AI 编写覆盖人类知识各领域的“教材”：收集讲解材料，创建专家解法，设计可验证练习题，再在大规模 GPU 集群上训练。算法概念本身可以概括得很简单，但真正把它们在数万甚至数十万 GPU 上稳定运行，是非常复杂的分布式工程。

从这个角度看，预训练已经让模型读过大量人类教材，许多知识以有损压缩的方式沉淀在参数里。后训练、工具使用和 RL 做的事情，不只是“再塞一点知识”，更是让模型把这些知识以人类能理解、能检查、能交互的方式吐出来。当前大模型最薄弱的地方，往往不是完全没有见过某个领域，而是这个领域缺乏可靠评价标准，模型很难知道怎样才算真正做好。

## 22. 未来方向：多模态、智能体和长期学习

按今天的产品状态看，多模态、智能体和计算机使用已经不再只是遥远未来，而是已经部分实现并继续增强的方向。文本、音频、图像都可以 token 化或被编码成模型可处理的表示：音频可以切成频谱图片段，图像可以切成 patch，然后和文本 token 一起放进上下文。这样一个模型就能同时处理文字、声音和图像，实现听、说、看、画。

智能体（agents）也已经从研究概念进入产品和工程实践。普通聊天是“用户给一个孤立任务，模型回答后结束”；智能体式系统则会把任务拆成多步，持续执行几十秒、几分钟甚至更久，期间调用搜索、代码、浏览器、文件系统或其他工具，并定期汇报进展。人类的角色会从亲自执行每一步，逐渐转向设目标、给权限、看过程、验结果。

计算机使用（computer use）同样已经出现。ChatGPT Operator 这类系统让模型不只是回答，还能操作浏览器、键盘和鼠标。但模型仍然会犯错，行动能力越强，权限控制、沙箱、日志、人工确认和结果校验就越重要。

真正还没有完全解决的是测试时训练（test-time training）和长期记忆。当前大多数模型训练后参数固定，推理时主要是在固定参数下不断采样，改变的是上下文窗口，而不是模型的长期参数。产品里可以有“记忆”功能，把用户偏好、历史事实或外部资料重新注入上下文；但这不等于模型像人一样在完成任务过程中持续更新自己的能力。换句话说，模型训练好之后，“智商”大体已经固定，任务中能做的是读更多上下文、调用更多工具、展开更多推理，而不是自然地越用越学会新技能。随着任务变长、模态变多，仅靠扩展上下文窗口可能不够，需要新的长期记忆和在线学习机制。

## 23. 如何跟踪和使用模型

跟踪模型进展可以看 LM Arena，也就是原 LMSYS Chatbot Arena。它通过人类盲评比较模型回答，计算排行榜。这个榜单有用，但可能被游戏化，因此只能作为第一参考，最好针对自己的任务实际试用。

AI News newsletter 是另一个资源，更新频繁，覆盖广，顶部摘要通常有价值。X/Twitter 也很重要，很多 AI 论文、产品和讨论会首先在那里出现。

使用模型时，闭源强模型通常去对应官网：OpenAI 的 ChatGPT，Google 的 Gemini 或 AI Studio。开放权重模型可以通过 Together.ai 等推理服务商使用，例如 DeepSeek R1、Llama 等。基础模型比较少见，因为大多数服务商面向助手模型；Hyperbolic 曾提供 Llama 3.1 405B base，适合观察纯续写行为。小模型可以本地运行，LM Studio 可以加载蒸馏版或量化版模型，在本机 GPU 上对话。

## 24. 最终心理模型：强工具，不是权威

回到 ChatGPT 文本框：用户输入会被放进对话协议，切成 token 序列，模型从“assistant 开始回答”的位置继续补全 token。它之所以能给出有用回答，是因为预训练把互联网知识压缩进参数，SFT 让它模仿人类标注员的助手行为，RL/RLHF 又进一步塑造了推理方式和偏好。

对于 GPT-4o 这类模型，可以把输出理解成“一个受过 OpenAI 标注说明训练的人类标注员会如何写理想回答”的神经网络模拟。对于 o1、o3、DeepSeek R1 这类思考模型，还要加上强化学习中涌现出来的推理策略，它们不只是模仿人类标注员，也在可验证练习中发展出自己的问题求解过程。

但无论普通模型还是思考模型，都可能幻觉、数错、拼错、跳过心算、在简单问题上表现奇怪。最好的使用方式是把它当工具：用来获得灵感、生成初稿、整理资料、辅助编程、调用搜索和代码；同时检查它的工作，必要时提供原始材料，让它使用工具，并由人类对最终结果负责。

ChatGPT 背后不是魔法，而是一套由 tokenization、Transformer、预训练、监督微调、工具使用、RLHF 和强化学习组成的工程系统。理解这套系统，才能更有效地使用它，也更清楚什么时候必须保持怀疑。

### slide 17

未来方向和使用原则最终收束到一个心理模型：强工具，不是权威。

- 多模态会让文本、图像、音频、视频都进入 token 化和上下文处理框架，模型能看、听、说、写、画。
- 智能体会让模型从“回答一次”走向“持续执行任务”，例如分步骤操作网页、调用工具、汇报进度。
- 计算机使用让模型有更强行动能力，但行动能力越强，越需要权限控制、过程监督和结果校验。
- 长期记忆和测试时学习还没有完全解决。当前多数模型主要依靠固定参数和上下文窗口，不等于会像人一样持续学习。
- 实际使用时，重要材料直接给原文，事实问题打开搜索，精确计算运行代码，关键结论查来源。
- 模型输出要被当作可用草稿、推理助手、资料整理器和工具调度器，而不是最终权威。
